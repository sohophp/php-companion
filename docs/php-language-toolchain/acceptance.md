## 必备反例

- 相同短类名、多 namespace、function/const/class 别名以及大小写差异。
- Trait 冲突/别名、晚期静态绑定、私有同名成员、匿名类。
- 泛型循环、递归返回类型、巨大 Union、引用参数和未知副作用。
- 命名参数与参数 Rename、继承层级、工作区外公开 API 调用。
- Unicode、CRLF、无标题文档、未保存文档、快速连续编辑及取消。
- Composer 更新、删除/移动文件、大小写文件重命名、symlink 与 Remote URI。
- 多 Controller 渲染同一模板、动态模板名、动态上下文、桥接失联。
- 预算耗尽、缓存损坏、服务器重启、旧版本结果晚返回。

## 性能预算

以下 R1 预算于 2026-09-06 冻结，机器或语料差异必须写入报告；后续不得提高预算来关闭失败。`@php-companion/testkit` 导出同一组机器可读预算和 P50/P95/最大值统计，CI 与本地报告必须引用它，不能另写宽松数值。

| 指标 | 初始目标或记录要求 |
| --- | --- |
| 热查询 completion/hover/definition | P95 ≤ 150 ms，包含协议往返，排除用户输入等待 |
| 普通文件本地诊断 | P95 ≤ 500 ms，排除已声明的防抖时间 |
| 取消后停止分析 | ≤ 100 ms，长任务分段检查 |
| 激活 | 不同步扫描项目，不等待全量索引 |
| 冷索引 | 1k ≤ 8 s；10k ≤ 60 s；50k ≤ 300 s，同时记录首个可用结果时间 |
| 峰值 RSS | 1k ≤ 384 MiB；10k ≤ 768 MiB；50k ≤ 1536 MiB |
| 热缓存体积 | 1k ≤ 64 MiB；10k ≤ 512 MiB；50k ≤ 2560 MiB；长时间编辑不得无界增长 |
| 局部变更 | 记录受影响文件数与耗时，证明函数体编辑不会默认全量重建 |

冷热测量分开；每种规模至少运行 5 次，热查询至少采样 100 次；报告样本量、P50/P95/最大值、取消和失败率。冷索引语料由确定性生成器生成等长 PHP 文件，并同时用一个脱敏真实项目校验。不能只报告最快一次。冻结预算已经建立，但未经各平台实测的项目仍不可标记通过。

基准命令为 `pnpm benchmark:index -- <文件数> <重复次数>`；它生成固定 Composer/PSR-4 语料、运行真实 parser/index/semantic 链路、输出 JSON，并在 1k/10k/50k 标准规模超预算时返回非零。Linux x64 的 [1k](reports/index-1000-linux-x64-2026-09-06.json)、[10k](reports/index-10000-linux-x64-2026-09-06.json)、[50k](reports/index-50000-linux-x64-2026-09-06.json) 报告中，冷索引 P95 分别为 1497.03/13463.54/64712.98 ms，首个可用结果 P95 为 32.79/96.68/426.11 ms，峰值 RSS 为 115.1/168/323.8 MiB，均满足对应冻结预算。结果不代表尚未实测的平台。

持久分层基准命令为 `pnpm benchmark:persistence -- <文件数>`；它在同一 Composer 语料执行冷索引、全量热恢复、Symfony Controller/Twig 与 Doctrine PHP 事实恢复、Callable 事实恢复、继承派生事实失效和单条损坏缓存恢复。当前格式为 schema 73/v45：声明/签名、方法体实现、派生索引和框架事实各有独立 SHA-256，整体条目仍有封装摘要。历史 v44 三平台证据继续保留；v45 的记录边界见[声明与实现磁盘记录验收](reports/persistent-declaration-implementation-records-2026-09-15.md)，声明优先恢复和正文按需装载见[声明优先与实现按需装载验收](reports/deferred-implementation-loading-2026-09-15.md)。

连续编辑与恢复基准命令为 `pnpm benchmark:editing -- <测量次数> <预热次数>`。它通过真实 stdio Language Server 交替更新可区分的对象类型，逐次验证最新补全，测量更新到诊断、热补全、取消和 RSS，并破坏实际持久缓存后重启验证恢复。RSS 采样分别使用 Linux `/proc`、macOS `ps` 和 Windows PowerShell 的进程工作集。Linux x64 的 [1,000 次报告](reports/editing-resilience-linux-x64-2026-09-13.md)通过；当前候选还在 Linux x64、Windows x64 与 macOS arm64 分别完成 500 次 CI 测量并保存原始 JSON，见[跨平台候选验收报告](reports/cross-platform-candidate-2026-09-14.md)。

## 测试层次

1. parser/phpdoc/type-system 纯函数与标记 fixture 测试。
2. 增量编辑与全量分析结果一致性测试，包含随机编辑和错误恢复。
3. 索引/语义/重构跨文件集成与缓存版本测试。
4. LSP 生命周期、取消、版本同步、能力协商和请求结果测试。
5. 真实 Extension Host 中的文本、选区、Preview、Undo/Redo 和格式化行为。
6. 打包 VSIX 干净 Profile 测试，验证实际发布资源和组合扩展。
7. 脱敏真实项目持续操作、平台矩阵、性能与故障恢复。

可信 PHP fixtures 可使用对应版本运行时进行语法/行为对照；PHPStan/Psalm 仅辅助发现差异，不能把其输出直接当作本项目语义实现或唯一真值。Winstar 内的 PHP 命令始终经 `bin/php-runtime`；旧版本对照在独立测试环境运行。
