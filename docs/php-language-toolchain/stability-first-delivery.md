# 稳定版优先的执行计划

日期：2026-09-27。此计划把现有 R1 能力收口为可持续使用的交付范围，再改善体验，最后完成 R4 全部验收。当前公开版本为 0.4.12；发布后的源码增量尚未进入公开 VSIX。进度和证据仍以[当前执行记录](reports/open-source-pack-current-priority-2026-09-27.md)及[验收清单](acceptance.md)为准。

## 第一阶段：能用且稳定

冻结当前 10 项 Open Source Pack，不增加默认扩展或新的通用 PHP Language Server。交付范围限于独立 Composer 项目中的普通 PHP 输入、补全、参数提示、Hover、Definition、Implementation、References、未保存编辑反馈、确定性导入，以及已经声明并验证的生成与重构支持域。Symfony 和 Twig 只验收现有明确所有者及其已支持的操作链。

按以下顺序执行，每项留下版本、输入、预期结果、实际结果和验证层级：

1. 在发布后源码上运行完整质量门禁，先处理回归；不因零散新功能延后候选。
2. 在独立 Composer 项目和当前 10 项 Pack 源码宿主复核 C1/C2 的连续输入、导航与未保存反馈。只修复可复现的错误结果、旧结果或明显卡顿；同一批最多处理三个按用户影响排序的问题。
3. 对 Import、Rename、Safe Move 和类型生成的已支持路径核对预览、取消、应用和一次 Undo/Redo。无法证明安全的路径须明确拒绝或列为限制，不把失败路径当成已验收能力。
4. 集中冻结 Core、Symfony、Pack 和外部成员版本，运行候选门禁；在真实 WSL Remote Profile 核对运行位置、唯一 PHP Provider、工具路径和完整操作链。源码宿主、CI 和 VSIX 安装记录分别报告。
5. 发布候选须无支持范围内的阻断性回归，且列明限制、安装与回退步骤。真人编辑器验收未完成时标为候选，不能称为已验收稳定版。

预计 Codex 连续执行后 1–2 周形成候选，真实环境验收与修复后约 2–3 周判断是否可称稳定版。这是日历估算，不是承诺发布日期；每批结束用实际缺口重估。

## 第二阶段：好用

在稳定范围内按用户可见影响改善 C1/C2 的准确性、等待和提示，再扩大 C3 高频重构的可证明支持域。每批以一条真实操作链为单位，先固定失败和合法反例，再实现、验证和记录限制。预计稳定版后约 1–2 个月重新评估体验目标。

## 第三阶段：功能全

继续按[长期路线图](roadmap.md)完成剩余 P0–P9，并逐项关闭[最终 F01–F14 验收](acceptance.md)。框架版本、PHP 版本、Windows/Linux/macOS、WSL Remote、真实项目规模和长会话分别保留证据。此阶段不能由稳定版发布自动算作完成。

## 防止问题拖住交付

每个问题先限定一个可复现输入、一个待验证假设和一轮定向验证。若该假设失败且没有新的证据，记录结果并转到下一项；重新调查须有新的用户复现、上游实现证据或可验证的替代方案。`WorkspaceEdit.createFile` 最终兜底的 Redo 已有失败探针，当前不再重复尝试同类编辑写法。它作为独立限制与最终验收缺口跟踪，不能被误报为修复，也不阻塞其它能力的开发。

日常源码增量运行相关包、真实 LSP 和受影响的 Extension Host 测试；只在候选冻结时统一生成三份 VSIX、验证组合并考虑发布。每批报告已完成、未通过、已停止调查的问题和下一批最多三个优先项。
