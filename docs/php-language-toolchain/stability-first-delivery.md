- **停止条件**：不足50ms或等价边界不成立，结束本轮CPU热点调查，不追加同类采样或重开已拒绝方向；原500/150ms缺口、人工及远程验收分别保留。

## 第一阶段：能用，收口正式版本的日常使用

**范围冻结**：保持现有 Pack 和功能所有者；优先验收独立 Composer 项目中的输入、补全、Hover、参数提示、导航、References、导入，以及已声明支持的生成与重构。Symfony/Twig 继续按已有职责协作。

### 批次 A：正式构建与实际使用对齐

1. 将正式提交、Core/Symfony 构建摘要、Pack/外部扩展版本和 PHP 运行时作为验收基线；复用同构建已有门禁，只补未覆盖或受变更影响的检查。
2. 在重载后的实际 WSL Remote 窗口核对运行位置、实际加载构建、唯一通用 PHP Provider 和工具路径。真人操作与隔离 Extension Host 自动化分别记录。
3. 完成一条日常操作链：打开项目 → 未保存输入 → 补全/提示/导航/引用 → 导入或生成 → 预览/取消/应用 → 保存 → 单次 Undo/Redo → 格式化 → 测试与调试。涉及编辑和故障注入的业务项目验证使用隔离副本；原项目只读回归。
4. 按错误结果、数据修改风险、明显等待排序，整理最多三个优先问题。缺失证据记录为未执行；已经复现的失败记录为已执行但失败。

**产物**：正式版本使用报告、支持场景与限制清单、安装/回退说明。**退出条件**：声明的日常操作链通过，支持范围内无未关闭的阻断性缺陷，人工 WSL 证据齐备。当前状态为已发行、已安装、真人验收待完成。

窗口重载和人工操作由真实环境验收提供；等待期间可独立推进性能分析、缺口审计和测试可靠性，不能把等待当作验收通过。

## 日常执行与调查规则

1. 每批最多三个优先问题，优先一个可明确收口的主问题；当前只实施性能与稳定性修复，暂缓功能扩展。
2. 单个问题先固定复现、验证一个假设并记录结果；没有新证据时转向独立任务。只有新的用户复现、实现证据或有区别的可验证方案才能重新调查。
3. 支持范围内阻断问题保持开放；转向独立工作不能据此宣布该阶段完成。性能原型需有同输入的稳定收益证据才能进入稳定候选，完整回归通过只证明其回归范围；没有收益的原型在运行任务终态之后收口或撤回。改变最终范围须有用户确认。
4. 日常改动先运行受影响包、真实 LSP 和受影响编辑器测试；阶段候选冻结后集中执行完整门禁。等待运行终态后再审计，不因慢或单项绿色重启、截断整轮。
5. 报告使用“已执行并通过 / 已执行但失败 / 未执行”，附源码/构建、输入、环境、命令与报告路径。人工操作、隔离编辑器自动化、CI 和安装核对分别列出。
6. 按用户既有要求在同一分支开发并保留无关修改；提交、推送、PR、打包、Profile 更新和公开发布按当次明确授权执行。实施期间先完成本地修复与必要验证；本轮调整优先级不改变运行中的回归输入。
