# 稳定版优先的执行计划

日期：2026-09-27。此计划把现有 R1 能力收口为可持续使用的交付范围，再改善体验，最后完成 R4 全部验收。当前公开版本为 0.4.12；发布后的源码增量已形成未发布的[0.4.13 候选](reports/sophp-0413-stable-candidate-2026-09-28.md)。进度和证据仍以[当前执行记录](reports/open-source-pack-current-priority-2026-09-27.md)及[验收清单](acceptance.md)为准。

## 第一阶段：能用且稳定

### 当前执行约束（2026-10-02）

以下约束按用户后续要求执行，优先于本文旧候选节奏和工期表：同一开发分支保留未提交修改，日常推进源码及相关本地验证，不例行提交、推送、PR、CI、打包或发布。用户要求更新 Profile 或开始真人测试时，再按实际变化生成必要的安装候选；补全专项只需 Core 候选时不重做三份 VSIX。真人使用可随时反馈并在同一分支修复，不建立独立真人测试分支。

本文 2026-09-27 的版本、组合数量和时间估算是历史候选快照；当前构建与通过范围以[执行记录](future-core-plan.md)及对应报告为准。自动化不替代真实 WSL 使用，外部格式化器的修补副本也不等于默认 Pack 已采纳修复。

冻结当前 10 项 Open Source Pack，不增加默认扩展或新的通用 PHP Language Server。交付范围限于独立 Composer 项目中的普通 PHP 输入、补全、参数提示、Hover、Definition、Implementation、References、未保存编辑反馈、确定性导入，以及已经声明并验证的生成与重构支持域。Symfony 和 Twig 只验收现有明确所有者及其已支持的操作链。

按以下顺序执行，每项留下版本、输入、预期结果、实际结果和验证层级：

1. 在发布后源码上运行完整质量门禁，先处理回归；不因零散新功能延后候选。
2. 在独立 Composer 项目和当前 10 项 Pack 源码宿主复核 C1/C2 的连续输入、导航与未保存反馈。只修复可复现的错误结果、旧结果或明显卡顿；同一批最多处理三个按用户影响排序的问题。
3. 对 Import、Rename、Safe Move 和类型生成的已支持路径核对预览、取消、应用和一次 Undo/Redo。无法证明安全的路径须明确拒绝或列为限制，不把失败路径当成已验收能力。
4. 集中冻结 Core、Symfony、Pack 和外部成员版本，运行候选门禁；在真实 WSL Remote Profile 核对运行位置、唯一 PHP Provider、工具路径和完整操作链。源码宿主、CI 和 VSIX 安装记录分别报告。
5. 发布候选须无支持范围内的阻断性回归，且列明限制、安装与回退步骤。真人编辑器验收未完成时标为候选，不能称为已验收稳定版。

2026-09-29 的[发布后源码完整门禁与连续编辑复核](reports/post-source-full-gate-2026-09-29.md)已让当前未提交增量通过 `pnpm test`、`pnpm typecheck`、`pnpm lint`、500 次真实 stdio 连续编辑基准和完整 10 项 Pack 源码宿主。此结果完成第 1 项的当前源码回归检查，并给第 2 项提供独立 Composer 宿主证据；其它持续使用场景、第 3–5 项及真实 WSL Remote 验收仍逐项进行。

随后第 3 项的[跨 namespace 导入名称冲突](reports/c3-import-declaration-namespace-collision-2026-09-29.md)已从红灯修复到语义全量、真实 LSP 与 C3 隔离宿主回归通过；现有 Import、Rename、Safe Move 和类型生成链未出现回归。新增场景的真实 WSL UI 仍待候选验收。

第 2 项又补齐[独立未完成单词旁的顶层变量诊断](reports/c2-partial-word-independent-variable-diagnostic-2026-09-29.md)：`func` 的局部语法错误不再撤下后方可证明的 `$a` 警告；不确定的未闭合声明仍保持抑制。语义、真实 LSP、定向和完整 C2 隔离宿主均通过，真实 WSL 显示仍待验收。

上述两个后续源码增量已通过[完整回归门禁](reports/post-c2-c3-source-gate-2026-09-29.md)：语义 487 项、语言服务器 444 项通过及 1 项跳过，组件与根扩展测试、Lint 和类型检查通过。真实 WSL UI 仍单独验收。

截至 2026-09-27，本地候选已经完成源码、打包宿主与 24 个组件包门禁；[当前缺口和证据](reports/stability-first-candidate-gate-2026-09-27.md)单独记录。以下时间从当前候选继续计算，**Codex 工作时间**和**需要人在编辑器操作的时间**分开估算：

| 批次 | 交付结果 | 预计用时 | 停止条件 |
| --- | --- | --- | --- |
| A. 候选收口 | 同源提交的跨平台 CI、冻结安装与限制报告 | Codex 约 0.5–1 天；CI 排队另计 | 仅修支持范围内的阻断回归；单个难题一轮复现、假设与定向验证后仍无解就记录并转下一项 |
| B. 真实环境验收 | WSL 集成终端严格预检、Reload Window 后扩展宿主和工具路径核对、独立 Composer 项目连续编辑 | 人工操作至少 2 小时，通常留 0.5–1 天；Codex 跟进约 0.5 天 | 没有真实编辑器证据时停在“候选”，不把自动门禁记成稳定版验收 |
| C. 正式交付 | 针对验收中最多三个阻断问题修复或收缩支持范围、版本升级、三份同版本 VSIX 与发布门禁 | 若无新回归，Codex 约 0.5–1 天；每个阻断问题另行估算 | 跨平台及真实环境门禁通过才发布；发布后核对公开产物 |

无新增阻断时，目标是约 **3–7 个日历日**判断能否发布首个稳定支持范围版本；其中 Codex 实际执行约 **1.5–2.5 个工作日**，人工验收约 **0.5–1 天**。这是基于现有候选的估算，不是对未知回归或 CI 排队时间的承诺。若 B 阶段无法完成，保留候选并继续其它独立工作，不无限延长“快要发布”的状态。

## 第二阶段：好用

在稳定范围内按用户可见影响改善 C1/C2 的准确性、等待和提示，再扩大 C3 高频重构的可证明支持域。每批以一条真实操作链为单位，先固定失败和合法反例，再实现、验证和记录限制。预计稳定版后用 **4–8 周日历时间**重新评估体验目标；按每周可投入的 Codex 与人工验收时间重排，不视作连续编码工时。

## 第三阶段：功能全

继续按[长期路线图](roadmap.md)完成剩余 P0–P9，并逐项关闭[最终 F01–F14 验收](acceptance.md)。框架版本、PHP 版本、Windows/Linux/macOS、WSL Remote、真实项目规模和长会话分别保留证据。此阶段不能由稳定版发布自动算作完成。

## 防止问题拖住交付

每个问题先限定一个可复现输入、一个待验证假设和一轮定向验证。若该假设失败且没有新的证据，记录结果并转到下一项；重新调查须有新的用户复现、上游实现证据或可验证的替代方案。`WorkspaceEdit.createFile` 的 Redo 已有失败探针，不能被误报为 VS Code 修复。本地 `file` 工作区已取消这个最终兜底，三条移动都失败时明确拒绝创建；其它文件系统的 `createFile` Redo 与真实 WSL Remote 行为仍待验收，见[收口记录](reports/c3-createfile-redo-resolution-2026-09-28.md)。

日常源码增量运行相关包、真实 LSP 和受影响的 Extension Host 测试。安装候选、组合冻结和公开发布分别按用户明确要求执行，不将开发测试通过作为例行打包或发布触发器。每批报告已完成、未通过、已停止调查的问题和下一批最多三个优先项。
