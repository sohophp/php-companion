# 分批上线与精准功能策略

本文件取代原计划“完成全部 P0–P9 后才具备交付资格”的串行发布安排。P0–P9 保留为工程任务清单；交付按 R0–R4 执行。状态：已确认并实施中，当前能力和缺口以 `status.md` 为准。

## 原则

先把少量高频 PHP 功能做准，再通过免费且许可合适的插件组成完整日常开发环境。逐渐替换的是存在质量或集成缺口的能力，不以替换成熟 JSON/YAML 基础服务、Twig 或 formatter 为目标。

“完整使用”指已声明项目与工作流可以从编码、导航、格式化到测试和调试完成闭环，不等于支持全部 PHP 动态语义或全部 PhpStorm 功能。每版必须列出已支持场景、外部提供者和限制。

自研核心仍是主线。非 PHP 插件无法补上 PHP 类型推断；核心未达标时不得把纯扩展合集叫作独立 PHP 替代版。

## R0：免费工具组合与首发规格

目标：尽早形成可验证的免费工具组合，完成核心开发所需的精准基线。对应 P0、少量 P1 和外部工具集成。

- [x] 验证默认组合成员的许可、实际免费功能、PHP 版本、安装方式与维护状态；冻结版本的完整 Open Source Profile 已通过 Linux、Windows 与 macOS 自动门禁，Windows 客户端连接 WSL Remote 和人工 UI 仍留给 R4。
- [x] 核查现有 Open Source Pack 的每个成员；闭源 Database Client、非核心扩展及存在 Provider 冲突的 Symfony Language Tools 0.20.1/0.20.2 已移出默认安装和受支持 Profile，八项默认成员已确定许可证与职责边界；Red Hat XML 与 Symfony 历史隔离评估单独记录。
- [x] 默认插件及职责边界已固定在 integrations.md；JSON/HTML/CSS/JS 使用 VS Code 内建服务。
- [x] Symfony Language Tools 0.20.1 Linux x64 的静态索引能力已完成历史评估，但它与 0.20.2 都在重复组合门禁中干扰普通 PHP Rename，且没有关闭该 Provider 的设置；当前不提供自动或手动推荐安装。静态路由候选由 Companion 在可证明源码范围内补齐，上游修复后重新执行三平台门禁。
- [x] 首发 PHP 高频样例、S01–S08 质量门槛及功能所有者表已经冻结并完成 Linux/WSL 审计。
- [x] 自研核心已通过 R1，未引入临时 PHP LS；手动 Intelephense 旧工作流只保留兼容回归。

临时 PHP LS 优先验证 Phpactor，但它不是已通过验证的默认选型。必须检查性能、准确性、PHP 8.5 语法及 WSL 限制；不适用时继续验证候选或等待 R1，不用闭源免费软件冒充开源。不把适配临时核心扩大为重写其核心的项目。

R0 不含自研 PHP LS 完成声明。只有临时 PHP 核心和整套工具闭环实测通过时，才能交付“过渡组合版”；否则 R0 仅交付规格与配置方案。

## R1：精准 PHP 核心首发

目标：交付自研核心负责 PHP 日常高频能力、免费插件负责其他语言和辅助工具的可安装版本。对应 P1–P4 的必要子集以及 P6/P7 的既有功能迁移。

必需能力：

- [x] 原生签名与常用 PHPDoc 类型下的类、函数、成员补全。
- [x] Hover、参数提示、定义跳转、文档/工作区符号。
- [x] namespace/use、继承、接口、Trait、可见性和 self/parent/static 的常见路径。
- [x] Composer 项目、vendor 与内建符号，未保存文档和增量索引。
- [x] 基础引用查找；class/interface/trait/enum 可从声明执行 F2，以一次可撤销编辑同步规范 PSR-4 文件名、声明、跨文件引用和 PHPDoc，普通字符串保持不变；Safe Move 在证明不足时拒绝。
- [x] 文件生成、导入和整理 imports，不退化当前可用工作流。
- [x] 仅启用高置信度语法、namespace/PSR-4、重复声明等诊断。
- [x] 简单赋值、调用返回值、可空值判断的基础推断；复杂泛型和动态类型显式降级。
- [x] 免费工具组合实际完成格式化、Twig/YAML/JSON 编辑、测试和调试。

首发支持优先针对 Winstar PHP 8.5 的代表性日常代码和 Composer 项目。PHP 7.2–8.5 的完整矩阵逐版补齐；已有旧版本工作流不应回归，但不提前宣称新核心覆盖所有版本。若 Winstar 的必需闭环依赖某项泛型能力，应把最小必要实现提前，而不是删掉对应真实样例。

不作为首发阻塞项：完整控制流、高级泛型/条件类型、方法级跨层级 Rename、提取方法、修改签名、自研 Symfony/Doctrine 和跨 Twig 重构。这些进入 R2–R4。

退出条件：acceptance.md 的 S01–S08 全部通过。没有准确性证据的功能不默认启用。R1 独立 Profile 不安装其他通用 PHP LS；Symfony 框架增强只在已验证版本下作为可选组件。Linux/WSL 证据已记录；跨平台最终矩阵仍由 R4 完成。

## R2：类型与导航逐步增强

对应 P5 和 P6，按“一个语义能力 + 依赖它的编辑功能 + 正反例 + 性能报告”交付小版本。

顺序：控制流收窄 → 泛型 Repository/集合 → 数组形状/Callable → 模板推断/递归边界 → 高置信度类型诊断 → 实现跳转/类型层级/生成辅助。

每次扩展支持域都要增加固定验收样例。未知时降级仍须记录覆盖缺口，不能以全部返回 unknown 达到低误报。

## R3：安全重构与框架缺口

对应 P7 和 P8 的必要部分。先完善方法/属性/参数 Rename，再做提取、修改签名和跨文件变更。

Symfony/Doctrine 先继续使用经验证的免费增强插件。只有真实缺口、重复索引成本或无法满足精准要求时，才实现对应自研模块并逐项接管。先迁移 PHP 框架类型与上下文，Twig 始终由 twig-plus 处理。

替换必须先通过相同样例及真实编辑器对比，再停用旧提供者；无法单独关闭某项功能的外部插件按整个冲突能力组切换，禁止依赖 Provider 注册顺序“抢占”。

## R4：PhpStorm 式目标验收

完成剩余 P0–P9 与 F01–F14，形成自研 PHP 核心、可靠重构和一致框架工作流。长期继续复用 TwigPlus、成熟 formatter 与通用语言插件，不要求全部代码由 Companion 重写。

R1 首发通过不等于 R4 完成。开发目标持续至 R4；每次上线单独进行发布资格与授权确认。

## 精准门槛

1. 预先固定必需样例，期望候选不能漏掉；不适用成员不能混入；定义必须落到正确声明。
2. 使用完整候选断言、合法反例和未完成输入，而非“返回数组非空”测试。
3. 未知类型不猜测，有限结果明确记录；未知率、漏报、误报和失败分别统计。
4. 支持域内的诊断正反例全部正确；真实项目人工抽样另记分母和结果，不将测试集零误报扩大为全 PHP 零误报。
5. 重构只对已证明范围应用，冲突或版本过期中止；不能以全拒绝冒充重构可用。
6. 首发 UI 不展示未实现的菜单或空功能；限制写入功能状态页。

## 排期方式

R0 以 1–2 周验证窗口估算；R1 在冻结样例和完成解析审计后估算，通常仍是月级自研工程，不能承诺几周实现成熟 PHP 类型核心。对外最早可上线的是经验证的 R0 过渡组合；自研核心达到 R1 才切换默认。原先长期量级仅用于 R4，不再作为首次上线前置工期。
