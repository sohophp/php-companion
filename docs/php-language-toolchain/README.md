# PHP 自研语言工具链开发计划

状态：**实施中**。本计划于 2026-09-06 编写并开始执行，基于 PHP Companion 0.4.5 与本地 twig-plus 源码评估。

本目录是实施、阶段验收和最终验收的入口。当前已有自研语言服务器主链和部分 P2–P4 能力；阶段通过只表示一个里程碑完成，不以 Alpha、文档或部分功能代替最终目标。

## 发布策略

优先采用 [分批上线与精准功能策略](releases.md)：R0 免费工具组合 → R1 精准 PHP 核心首发 → R2 类型增强 → R3 重构和框架逐项替换 → R4 最终体验验收。P0–P9 为工程任务分解，不再要求全部完成后才首发。少量功能必须准确，通用语言和成熟工具优先复用。

## 最终目标

在不安装、不启用 Intelephense 或其他通用 PHP 语言服务器的干净 VS Code Profile 中，由 PHP Companion 自研语言服务器和类型系统提供稳定的 PHP 编码体验。在明确支持的 PHP 7.2–8.5 语义及真实项目场景中，完成补全、类型推断、导航、诊断、安全重构和框架联动，达到本文验收清单界定的 PhpStorm 式常用工作流。

Twig 编辑、解析、格式化、模板语义继续由 twig-plus 唯一负责；PHP 格式化选用 `junstyle.php-cs-fixer`，不自研 formatter。调试与测试执行复用现有扩展。

“接近 PhpStorm”以 [最终验收](acceptance.md) 为准，不表示复制其全部 IDE 功能，也不通过未经测量的覆盖百分比宣称等价。动态代码不能静态证明的范围必须明确说明，不伪造类型或完整重构结果。

## 执行与完成规则

1. 开发已经获得确认并持续实施；内部可逆工作不重复请求确认。
2. 第一批执行 R0 插件核验与精准规格，随后推进 R1 必需核心子集；按 R0–R4 分批交付，持续完成长期目标。P0–P2 是核心内部技术节点，不是首发产品验收。
3. 每阶段更新工作项和证据，不将“实现代码”“自动化通过”“真实编辑器验证”“发布验证”混为一谈。
4. 未通过阶段门槛时修复或明确记录阻塞，不提高预算、删掉反例、降低目标来宣布完成。
5. 内部可逆实施无需反复确认。改变产品目标、删减最终范围或公开发布需要另行确认；确认开发不等于授权发布 Marketplace、推送标签或对外发消息。
6. 开始阶段工作前检查 Git 状态，保留无关修改。不要修改业务项目配置或源码来制造验收通过；真实项目以只读分析和隔离副本为主。

## 当前事实与计划边界

- 当前扩展已有生成、导入、Rename、Safe Move 和自研语言服务器；独立安装、Open Source Pack 与 Recommended Pack 均默认启用。检测到 Intelephense 且用户没有显式选择时，自研服务器保持关闭，以保留既有单一 Provider 工作流。
- 自研主链已有 Composer 有界索引、基础 PHPDoc/类型系统、成员补全、Hover、Signature、Definition、References 和首批内建符号；控制流、高级类型、完整诊断和持久索引仍未完成。
- 稳定版 README 和 Release checklist 仍描述 0.4.5；预览能力与稳定能力分开说明。
- 采用 pnpm monorepo，完整组件具备独立 API、构建、测试、打包及安装能力；先验证核心包，按需公开发布，保持扩展 ID 与用户配置兼容。具体规则见 packaging.md。
- 估算量级：两名熟悉语言工具的开发者持续投入，Alpha 约 3–5 个月、复杂项目 Beta 约 8–12 个月、可靠重构与框架体验约 12–18 个月以上。此为排期参考，不是承诺；P2、P5 后根据证据重估。

## 已确认范围

执行范围为本目录 R0–R4 发布路线及 P0–P9 工程任务：自研 PHP 语义和类型核心、组件化语言服务器、现有功能迁移、twig-plus 协作、成熟格式化插件集成，以及最终验收。任务不得自动缩减为仅完成第一批；公开发布仍需单独确认。
