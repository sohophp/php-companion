# SoPHP 核心功能后续计划

日期：2026-09-24。本文从[长期工程路线图](roadmap.md)和[最终验收](acceptance.md)中抽出 **PHP 核心**的执行顺序；各项是否完成仍以[实施状态](status.md)及实际测试报告为准。本计划不改变 R0–R4 的最终目标，也不把已有 Alpha 证据当作最终验收。

## 核心的职责

SoPHP Core 负责 PHP 7.2–8.5 的解析、PHPDoc、Composer 项目发现、内建符号、类型与控制流、LSP 导航/诊断、PHP 代码编辑计划，以及 VS Code 中唯一的通用 PHP 语言服务。支持范围外的动态代码应给出 unknown 或拒绝不安全编辑，同时记录漏报范围；不能以全部返回 unknown 代替功能完成。

Symfony 的服务、路由、事件和 Controller 上下文继续由独立 SoPHP Symfony 扩展交付；Doctrine Entity/Repository 查询事实目前由独立 `framework-doctrine` 包提供，并由语言服务器消费，后续仍按 P8 的框架轨道验收。Twig 由 twig-plus 负责；格式化、调试、测试及扩展包继续使用已确定的提供者。Core 保留明确的 Provider/interop 契约，但这些框架和外部工具的功能清单不计入下表的通用 PHP 核心完成度。[P8 框架计划](roadmap.md)及 F09–F12 仍需独立执行。

## 当前起点

- R1 的 S01–S08 已有 Linux/WSL 首发候选证据；P1 组件和 LSP 主链已建立。P2、P4–P7 的完整支持域与 P0、P9 的最终验收仍开放。
- 当前语义快照为 schema 82；Linux x64 合成项目的 1k/10k/50k 索引、热缓存、1000 次编辑和局部变更满足已冻结预算，见[复测报告](reports/p9-schema82-linux-benchmarks-2026-09-23.md)。这些结果不代表 Windows、macOS 或真实 WSL Remote 长时间使用。
- F04 已有 References 的编号正例、文本反例、未完成输入与文件顶层赋值回归；补全、Hover、参数提示、定义、实现和引用的完整联合矩阵仍需补齐。[P9 审计](reports/p9-acceptance-audit-2026-09-23.md)列出了其余 F01–F14 的证据缺口。

## 执行顺序

| 顺序 | 核心交付 | 具体工作 | 完成证据 |
| --- | --- | --- | --- |
| C1：准确性基线 | 为 P0、F02–F04 建立可回归的通用 PHP 基线 | 审计 parser/index 的公开事实、作用域和缓存契约；给补全、Hover、Signature Help、Definition、Implementation、References 建立跨文件、namespace/use、Trait/继承、顶层代码、未保存修改、错误输入的编号输入。每组含正例、合法反例及未完成输入；PHP 7.2、8.1、8.5 先作为可运行锚点，再补齐九个目标次版本。 | 独立 PHP 项目与真实 stdio 返回精确候选及范围；冷/热缓存、增量修改结果一致；公开[版本矩阵](version-matrix.md)逐项注明已支持、unknown 与拒绝。 |
| C2：类型与控制流 | 完成 P2–P5 的共同语义路径 | 独立 PHPDoc AST 区分类型、参数名和说明；补齐目标 PHP 版本和已启用扩展的内建签名；使局部赋值、调用返回、泛型集合/数组形状、Callable、继承模板及控制流合流共用同一类型事实。优先处理 C1 输入暴露的实际缺口，动态调用、歧义层级和预算耗尽保持保守。 | 同一类型事实同时驱动补全、Hover、Signature Help、导航与参数诊断；跨版本正反例、缓存恢复和修改失效通过；不新增已知的伪成员或伪定义。 |
| C3：可靠诊断与编辑 | 完成 P6–P7、F06–F08 的声明支持范围 | 把未完成索引、未知类型、快速编辑和取消纳入诊断反例；逐项完善 import、生成、Rename、Safe Move、Extract Interface/Method、修改签名、移动成员。每项先固定可证明的支持域、冲突和拒绝条件，再生成单个可预览的 WorkspaceEdit。 | 真实编辑器中预览、应用、取消、一次 Undo/Redo 均通过；版本过期、动态引用、工作区外公开 API、歧义或不完整索引拒绝危险编辑；旧工作流回归无退化。 |
| C4：资格验证 | 完成核心的 P9 与 F01–F08、F13–F14 | 在干净 Profile 中确认 Core 是唯一通用 PHP LS；完成九个 PHP 次版本、Windows/Linux/macOS 与 Windows+WSL Remote、1k/10k/50k、缓存损坏、取消/重启、长时间编辑、命令/设置迁移及本地化矩阵。独立真实项目只读验证，并记录机器、版本、样本量和全部失败。 | 冻结预算不放宽；源码测试、真实 LSP、Extension Host、真实操作分别有报告。最终交付包含可安装候选、支持清单、限制、安装与回退说明；F01–F08、F13–F14 逐项有足够证据。 |

C1 是下一阶段的工作入口；C2、C3 中已经实现的子集直接复用并审计，不重新开发。C4 中的自动门禁可提前持续运行，但候选资格以当前源码和当前 VSIX 的对应证据判定。

## 下一批具体任务

1. 扩充 F04 编号输入，先把有类型接收者、文件顶层变量和跨文件 Composer 类的六类导航/提示请求串成同一条真实 stdio 工作流；核对精确范围、声明开关、未保存版本和合法同名反例。
2. 对 parser 与 index 做 P0 数据契约审计：明确每条事实的来源、完整性、作用域、失效条件与 schema 迁移；从审计发现的真实错误进入 C1/C2 修复，不扩大到项目专用规则。
3. 为 C2 选择最影响 C1 工作流的类型缺口，按“独立输入 → 语义与 LSP 修复 → 缓存/增量回归”完成一个可验收增量，再进入下一项。

每个增量先运行相关包测试、类型检查、Lint 和真实 stdio 定向回归。影响 parser、缓存或索引时再运行对应完整回归与性能基准。**不为每个增量打包四份 VSIX**；仅在候选冻结或实际扩展宿主验证需要时构建对应产物。开发编辑器时不修改 Winstar 或其他被测业务项目代码。

## 完成判定

Core 的阶段完成需同时证明其声明支持域、合法反例、未完成输入、缓存/增量一致性及真实编辑器操作；一项自动测试通过不能代替整个阶段。C1–C4 和[验收文档](acceptance.md)中的核心条目均关闭后，才能称 SoPHP 核心开发完成。Symfony/Doctrine/Twig 与辅助工具的组合验收继续按 P8、F09–F12 完成；公开发布另行确认。
