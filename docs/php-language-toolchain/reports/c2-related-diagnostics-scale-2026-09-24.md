# C2 已打开文件增多时的诊断刷新

日期：2026-09-24。对[跨文件诊断修复](c2-cross-file-diagnostics-2026-09-24.md)做独立 Composer 项目基准：完整索引、PHP 8.5、一个 `Service::call()` 使用方，其余为无关的已打开 PHP 文件。未保存地把参数从 `int` 改为 `string`，以真实 stdio 接收时间计算使用方获得正确诊断的等待。可用 `node scripts/benchmark-related-diagnostics.mjs <使用方数量> [last]` 复现；`last` 把真正受影响的文件放在最后打开的位置。每项为本机单次样本，不是跨平台预算。

| 已打开使用方文件 | 原刷新：受影响文件等待 | 调整后：受影响文件等待 | 原使用方通知 | 调整后使用方通知 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 85 ms | 93 ms | 1 | 1 |
| 20 | 125 ms | 105 ms | 20 | 1 |
| 80 | 256 ms | 95 ms（受影响文件最后打开） | 80 | 1 |
| 128 | 372 ms | 98 ms（受影响文件最后打开） | 128 | 1 |

服务器现在优先处理源码中含变更类型或成员名称的已打开文件，再分批分析其余文件。名称匹配只决定顺序，不省略未匹配文件；间接依赖仍会重新核对。诊断内容和文档版本都与上次发布相同时，跨文件刷新不再给客户端发送重复通知。额外两次本机复测中，80 和 128 个文件且受影响文件最后打开时分别约 95、95 ms，使用方通知各 1 条。定向 stdio 回归同时覆盖标准 LSP 和 SoPHP 带版本通知：参数类型诊断的出现、消失、关闭恢复，以及无关已打开文件无重复结果；默认 `onDemand` 隔离宿主的快速编辑往返仍以退出码 0 通过。

基准没有测量所有后台重算完成时间，也没有测数小时会话、Remote、跨根依赖或大量复杂 PHP 文件。若变更符号不能在使用方源码中直接匹配，正确结果仍会发布，但可能排在后续批次。此次未修改业务项目，也未生成 VSIX。
