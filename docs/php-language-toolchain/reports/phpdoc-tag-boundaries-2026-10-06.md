日期：2026-10-06；基线 `55dda315`。当前产品 bundle SHA-256 `64793c2152b39eeb152883af8c06218fd1695adb3beee395274ef9676d7aba12`。[结构化证据](phpdoc-tag-boundaries-2026-10-06.json)保留原失败、正式结果、完整 UI runner 源码、资产／输入摘要与范围。

## 已修复的实际问题

PHPDoc 的标签识别只检查词边界，导致未知的 `@var-extra`、`@return-extra`、`@param-out` 等被截成支持的短标签。额外的 malformed `var`／`return` 会进入原方言优先级规则，覆盖前面正确的注释类型，使属性、函数与方法返回值的成员补全和跳转消失。改为识别完整标签名；已支持的复合标签、格式错误输入和 UTF-16 范围保持。

固定的 21 条语义场景在旧 PHPDoc 编译模块下全部失败于正确成员缺失；修复后的三种声明、三方言和两种树保留模式恢复，来源未保存变为 Other 时旧成员／跳转撤回，恢复 Row 时重新可用。完整、声明及源码声明三种 JSON 往返均保持结果。最初后验测试错误地要求 enriched semantic Definition 对象只包含位置三个字段，18 条因此失败；改为核对完整位置数组，不改变候选、位置、更新或撤回要求。原结果保留。

[`@param-out` 的 PHPStan 语义](https://phpstan.org/writing-php-code/phpdocs-basics#setting-parameter-type-passed-by-reference)是按引用参数在调用后的类型。本批只纠正标签识别，不实现它的输出类型契约；不把未知标签伪装为普通 `@param`。

## 冷查询中发现的函数来源缺口

真实 stdio 首次查询中，Composer `autoload.files` 内的函数尚未读取声明，赋值接收者没有返回值类型；先前两种默认模式都会缺少成员。共享有界表达式来源收集现在可取得具名函数依赖，规范化显式 alias 和 `namespace\` 名称，动态 callable 和其它词法作用域保持无依赖。它只提供声明读取来源，不猜测返回值。

成员候选为空时，服务器复用既有的 `hydrateOnDemandSymbolImports()`，读取 Composer 与依赖包显式自动加载文件的声明，再用原类型加载链和语义规则生成结果。沿用单文件大小限制、256 候选上限、超过上限时已有 Worker 搜索预算，以及取消／文档版本检查；没有同步全项目扫描、执行业务 PHP、增加配置或改变其它函数发现策略。

初始协议辅助客户端把对端请求混入同 ID 的响应集合，首轮失败；分离对端请求后，四组合均明确失败于 `$item` 的冷函数返回值补全。原失败保留。一次复用现有加载路径的源码方案解决该缺口，未靠等待索引或预热取绿。
