# 同项目 Controller 并行扫描合并

2026-10-04，用户要求继续路线图后推进的 C1 源码批次。此前安装候选的旧 Symfony 快照限制已修正，本批处理另一项独立缺口：并行 interop 请求没有共享正在执行的扫描。

## 修正

同一项目、epoch 和索引 generation 的 Controller 请求共享正在执行的扫描，每个调用者独立取消。全部取消后，不将新请求挂到已放弃任务；旧结果不能给新任务留下成功标记。Provider 变更、项目移除和关闭时清理等待者与任务。项目 epoch 改变仍允许有限重试；未合并不同项目或不同版本，不隐藏进度或放宽事实验证。

## 证据

- 修改前，真实 stdio 回归复现两个 Provider 调用，单次共享断言失败。测试使用独立 Composer fixture 和受控 Provider 闸门，没有修改业务代码。
- PHP 7.2／8.5 × 单个调用者取消／全部取消后立即重试，共 4 项通过：正常请求保留正确上下文，重复查询复用结果，每个 Finding 只结束一次，原始文件字节不变。
- 当前源码与 Core bundle 构建通过；根 noEmit 和 Extension Host 输入 noEmit 通过。
- 上述 4 项加既有 Controller 上下文的 4 项定向 stdio，共 8 项通过，15.36 秒；同文件其它 439 项跳过，不称当前完整协议回归。
- 实际 Composer 项目只读探针：2535 文件、197 候选，3 个同时发出的请求均返回一致的 24 个上下文；仅 1 次候选扫描，Finding begin／end 各 1 次，协议错误 0。三个冷请求共享约 15.26 秒等待，不把冷等待写成热查询分位数或真人 UI 结果。

实项目原始结果为 /tmp/sophp-controller-concurrent-proof.json，独立临时缓存及进程已清理。上述自动化不替代真实 WSL 操作；文件变更导致的必要重新准备、全版本／跨平台及长会话仍按后续计划验证。
