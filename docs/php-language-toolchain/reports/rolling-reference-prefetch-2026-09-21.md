# 首次 References：有界连续预读

日期：2026-09-21。源码基线：`72fd4a9`。

## 原因与实现

上一轮将缓存压缩移至 worker 后，冷查询的候选阶段仍约 8 秒。新的 CPU 采样中，主线程约有 3,090 个 idle 样本；旧实现必须等待一批 32 个文件全部完成准备后才开始语义提交，慢文件使同批已经准备好的文件继续等待。

索引器改为有界连续预读：保持最多 `readConcurrency` 个待消费的文件准备任务，当前文件准备完成即可按原路径顺序提交，并补入后续文件。源码解析与缓存预恢复沿用同一机制。语义回调顺序、候选集合、缓存格式及文件/字节预算不变；取消后不再提交后续文件。已经派发的少量准备任务可能继续结束，但不会提交语义结果，拒绝的 Promise 有回退处理。

新增回归以显式同步信号让后一个文件等待前一个文件提交，验证没有整批等待，同时检查准备并发上限和路径顺序；另覆盖已有预读任务时的取消行为。
