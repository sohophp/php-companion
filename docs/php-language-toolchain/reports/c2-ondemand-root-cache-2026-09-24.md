# C2 按需缓存上限与嵌套 Composer 根归属

日期：2026-09-24。使用独立临时 Composer 项目、真实 Language Server stdio 和默认 `onDemand` 模式；没有修改业务项目或打包 VSIX。

## 发现与修复

一个目录最初属于父 Composer 项目时，先打开再关闭其中的 PHP 声明文件会把磁盘类型事实留在父项目的近期文件缓存。后来该目录新增自己的 `composer.json`，Core 已把新打开的文件指向子项目，但父项目仍能从旧缓存补全子项目方法。新增用例先复现了父项目错误提供 `nestedOnly` 的结果。

根发现现在先把新根范围内已经加载的 PHP 文件事实从父项目迁移到子项目，转移相关索引集合和近期关闭缓存，再发布新根。父、子项目的候选结果均失效；已打开文件优先使用未保存缓冲区，已关闭文件继续使用磁盘快照。已排队的文件监视变化在磁盘读取后重查根归属，避免把新根文件再次写回父项目。用例验证迁移后父项目不再提供 `nestedOnly`，子项目仍能提供；随后监视器把磁盘声明改为 `nestedLater`，新结果只出现在子项目。已安装的 Composer 路径依赖仍由原项目拥有，沿用现有 vendor 归属规则。

另一个 stdio 用例在一个 Composer 根中顺序打开并关闭 257 个小 PHP 文件，使用仅在 `testMode` 开启的只读请求检查近期关闭缓存：保留 256 个，最早文件被淘汰；重新打开最早文件并再次关闭后，它被保留，原第二个文件被淘汰。该用例检验缓存数量和最近使用顺序，不把 257 次短操作当作长会话内存或实际 UI 延迟验收。

Language Server 全套在根迁移与缓存上限实现后通过 18 个测试文件、335 项，1 项按原设置跳过。随后将新根发布顺序与排队 watcher 的归属检查收紧；最终源码重新构建，嵌套根、路径依赖、vendor 归属、PHPDoc 编辑及 257 文件缓存等相关真实 stdio 用例 10 项通过，TypeScript、ESLint 与差异检查通过。全套结果覆盖主要实现，最终时序收紧由相关回归覆盖。本轮没有运行完整 Pack 宿主或重建 VSIX。Remote、完整组合和数小时真实编辑，仍须分别按计划验收。
