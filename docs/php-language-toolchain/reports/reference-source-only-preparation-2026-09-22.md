# 项目源码预备索引实验：首次 References

此实验只在语言服务器 `testMode` 与 `experimentalReferenceSourceOnly` 同时启用时运行；扩展的默认行为没有改变。目标是把项目源码的完整语义分析移到空闲阶段，首次 References 只补齐实际用到的 vendor 接收者类型，避免再次扫描 2,289 个项目文件。索引仍受 Composer 源目录、文件数量及总字节限制；索引不完整时退回原有按需路径。

## 实现边界

- 后台以独立 worker 池准备完整项目 PHP 事实，主线程按稳定路径顺序提交，依旧使用现有语义工作区和持久缓存。首次查询会停止尚未完成的预备 worker，避免与按需查询争抢 CPU。
- 恢复完整事实之前逐文件读取并核对 SHA-256；时间戳和文件大小相同不足以证明引用事实仍有效。已打开但内容与磁盘不同的文件使预备状态失效，后续查询退回原有扫描。
- Doctrine、Symfony 服务与事件、通用语义提供者及 callable 事实就绪后才允许跳过候选扫描。控制器模板上下文继续独立准备；PHP References 查询不读取该上下文。
- 项目方法调用可继续按接收者类型补齐 vendor 声明。没有证明预备结果覆盖查询所需事实时，不将项目源码索引当成完整依赖索引。

## 验证

使用打包后的服务器和独立缓存目录，在 Winstar `AdminPasswordChangeGuard.php` 最后一个 `get` 上先发 References 再发 Definition。基准门禁逐一比较全部位置的 SHA-256；127 处 References 的摘要为 `64da8a3d32297acd6ff06ec6e25ba54a940f2f81032f9936b85c238622aec531`，Definition 的 1 处摘要也与默认路径一致。

| 场景 | 等待后台准备 | 首次 References | 项目文件缓存 | 候选扫描 |
| --- | ---: | ---: | ---: | --- |
| 默认按需 | 无 | 8,605 ms | 无 | 2,289 文件 |
| 实验冷启动 | 20 s | 3,774 ms | 0 / 2,289 | 无 |
| 实验重启 | 13 s | 3,716 ms | 2,289 / 2,289 | 无 |

冷启动索引结束约 23.8 秒，重启约 16.7 秒；引用事实早于完整控制器上下文结束而就绪。因此这些数字只证明**等待后的首次查询**改善，不能当作启动即点的延迟。默认模式仍约 8.6 秒，距满意的交互速度还有明显差距。

单命令重复此门禁：`pnpm check:references:source-only:winstar`。另用 `pnpm check:references:winstar` 核对默认路径。语言服务器定向 stdio/worker 测试 94 通过、1 跳过；索引包 37 项通过；改动文件 ESLint、TypeScript 构建与 diff 空白检查通过。定向回归包含 vendor 方法接收者补齐、未保存编辑后的退路，以及缓存元数据伪装但内容改变的重建。

### 后续测量：就绪事件与无变化打开

固定睡眠可能在事实尚未就绪时发起查询，造成按需退路，不能用作稳定的冷启动对照。门禁现在等待 `Reference source facts ready` 后立即查询，再等待索引缓存写入后才重启进程。一次 Winstar 冷启动约 18.0 秒、重启约 11.1 秒到达事实就绪；首查分别为 3,422 / 3,522 毫秒，127 个位置的完整摘要仍相同。默认按需门禁为 8,046 毫秒，完整摘要相同。

一次 `didOpen` 还会触发 `onDidChangeContent`。两处过去即使打开的内容与已索引磁盘文件相同，也会使已完成的 Symfony 容器事实失效，首查重跑提供者约 0.8 秒。实验路径现在会核对磁盘内容与语义更新结果后保留未变事实；本次两轮首查的容器阶段均为 0 毫秒。定向回归覆盖相同内容的 `didChange` 保持复用，以及未保存编辑后恢复原有扫描。

语义阶段仍约 2.2 秒。分段计时显示 410 个候选文件、1,271 个同名访问中，建语法树约 0.9 秒，接收者解析约 1.0 秒。曾试验在引用查询中省去建树，虽保持这组位置一致，但解析耗时升至约 6 秒；也试过在提供者运行期间先保留候选树，首查约 3.8 秒并增加峰值内存。这两组代码均已撤回。语法树为解析提供语句边界，单纯省略或提前建树不能证明改善。

此轮语言服务器全套测试 243 通过、1 跳过；打包服务器的冷启动/重启完整位置门禁、默认按需门禁、改动文件 ESLint、TypeScript 构建及 diff 空白检查均通过。这些自动验证仍不能替代真实 WSL Remote 的持续编辑验收。

### 选中符号后的后台预热

VS Code 扩展已有光标选中通知和按需模式的引用预热，但项目源码预备索引实验此前没有接入。实验路径现在在引用事实就绪后，针对当前选中方法补齐新载入的依赖接收者，直到已载入文件集合稳定；若 16 轮仍不能稳定，就不报告完整引用结果。随后只对这个选中的方法计算并缓存引用。真正编辑内容仍会使预热失效。

新增 `pnpm check:references:source-only-selected:winstar`，在冷启动和重启各等待引用事实与选中预热完成，再发首次 References。两轮首查分别为 **242 / 222 毫秒**，语义阶段分别为 **0 / 1 毫秒**，127 个位置的完整摘要与默认按需相同。后台索引到事实就绪约 18.6 / 11.2 秒，随后还有约 2.1 秒的选中预热；索引收尾可与其并行。因此这个数字只证明所需后台预热完成后的点击响应；未选中时实验路径仍约 3.5 秒，启动即点仍可退回约 8 秒的按需扫描。实验仍仅限 `testMode`，尚未发布新版 VSIX。

闭包补齐后，选中预热可与索引收尾并行。Winstar 的直接对照中，预热刚结束时点击为 224 毫秒，等索引收尾完成后再点击为 250 毫秒，两者位置摘要相同；此前等待索引收尾的代码已移除。预热完成不等于整个项目索引已经落盘，重启门禁仍会在退出前等缓存提交。

最终固定门禁复测为冷启动 202 毫秒、重启 186 毫秒，语义阶段各 1 毫秒，完整位置摘要不变，且没有候选扫描。语义包测试 295 通过，语言服务器测试 243 通过、1 跳过；移除索引收尾等待后又通过定向 stdio 回归及选中门禁。改动文件 lint、TypeScript 构建和 diff 空白检查通过。

## 未达到的目标

实验尚未对任意 Composer 项目、复杂动态接收者和真实 WSL Remote 持续编码完成准确性验收，因此不开放为默认设置。未预热的首次查询仍需约 2.2 秒的语义计算，加上路由检查约 0.6 秒；启动即点还可能退回按需扫描。下一步应检查不同项目规模、内存开销与即时点击的退路，只保留能维持完整位置一致的优化。

## Alpha 显式试用入口

现可在工作区设置中同时启用 `phpCompanion.indexing.mode: "experimental"` 和 `phpCompanion.indexing.experimentalSourceOnlyReferences: true`，然后执行 `Developer: Reload Window`，由实际扩展启动后台项目源码预备索引；不再要求 VS Code 测试宿主的 `testMode`。默认配置仍是 `onDemand`，不开启该试验。已有针对生产模式初始化的 stdio 回归，检查预备完成后的两处 vendor 方法引用、无候选重扫、相同内容编辑的复用、选中预热，以及真正修改后的失效。

同一正式 bundle 的 Winstar 门禁：默认模式立即点击 8,112 ms、127 处；实验模式在源码事实和选中语义都准备完之后，冷启动点击 213 ms，缓存重启点击 233 ms，均为同一 127 处完整位置摘要。实验冷启动约 19.3 秒、重启约 10.9 秒才报告源码事实就绪，另需约 2.2–2.3 秒选中语义预热；这些等待时间不计入点击响应。因此此设置改善空闲后的首次点击，**没有解决启动即点击的约 8 秒问题**。若预备尚未完成，服务器仍执行原有候选扫描。尚未在用户的 WSL Alpha Profile 安装和验收，不能视为正式默认功能。

另以 `testMode=false` 的初始化参数直接核对两个边界：`pnpm check:references:source-only-immediate:winstar` 在启动即点击时走完整候选扫描，8,564 ms、127 处；`pnpm check:references:source-only-selected:winstar` 等待事实和选中预热后，冷启动 230 ms、缓存重启 217 ms、各 127 处。三次完整位置摘要均为 `64da8a3d32297acd6ff06ec6e25ba54a940f2f81032f9936b85c238622aec531`。语言服务器全套 243 项通过、1 项跳过；生产模式初始化的聚焦 stdio 回归及改动文件 ESLint 通过。该分组命令直接运行已构建的正式 bundle，源码修改后须先构建语言服务器并运行 `node esbuild.mjs --production`，避免测到旧代码。
