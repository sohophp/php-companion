这是新增的实际生产服务器补充工作负载，不替换前置原四阶段基准。原 testkit 生成固定语料，PHP 8.5／progressive；每轮新建语料和缓存、先冷服务器、再用同一缓存启动新的暖服务器。运行实际 d426 bundle／两 WASM，无 testMode、profiler、强制 GC、查询预热或重试。1000 文件首轮作为初始门禁观察，在同一未改工作负载及输入下只计一次，随后串行扩大；任一原门禁失败即停止，不用复跑挑选绿色。

每次立即发送首次精确成员补全，验证首项、kind、detail、textEdit，再验证 Hover 和精确 Definition，未先等待诊断或索引就绪。随后核对完整项目文件数、项目就绪和引用事实就绪、索引自然结束，再对三种查询各执行 100 个热样本，每次检查结果。首次协议时间与热查询分开；不等于编辑器可见时间。完整原始热样本保留，各轮和五轮统计使用原 testkit；五样本 P95 等于最大值。

实际生产 indexLimits.maxFiles 明确设置为语料规模，单文件 512 KiB、总量至少 128 MiB；不是默认 10k 上限下的完整 50k 资格。progressive 按原设计只完成项目来源、排除依赖索引，因此完整项目计数／缓存命中／就绪分别验证，原 overall complete=false 保留，不能冒称完整 vendor 索引。冷命中 0、暖命中全部文件；暖恢复后原 schema 2 manifest 摘要保持。

服务器从初始化、真实 worker 线程、首次与热查询到 shutdown／自然退出均由 Linux wait4 读取实际子进程 high water，包含线程，不用驱动进程 RSS 代替。独立观察器探针故意退出 3，验证非零状态、stdin/stdout/stderr 透传、退出后峰值和真实 PID；另有初始未匹配／暂时不可读取的受控输入、错误身份拒绝，以及实际身份拒绝后仍回收并保存退出码／wait4 的四项控制，不计作产品案例。此前观察器第五轮失败及原始命令样本缺失保留，未证明具体启动竞态；本轮只增加严格身份取证断言，反向还原与原工作负载逐字相同，旧四轮未继承。该指标不包含语料生成／驱动内存，也不是多个独立进程并发内存的总和。全部实际命令行和服务器输入摘要保留。

冷索引原 8／60／300 秒、RSS 原 384／768／1536 MiB、缓存原 64／512／2560 MiB、热查询 P95 原 150 ms 均保持。冷索引门禁使用服务器实际 index start/end 区间，启动至就绪另列，不能混淆。暖恢复等待没有独立原硬阈值，仍需审查；不与历史未配对单样本或不同包级基准直接作性能改善比较。
