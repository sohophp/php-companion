# D107 PHP 7 旧式构造函数的安全重命名

日期：2026-10-05；基于 `6d2c8c7f`，继续 C1–C4 的构造语义与 Rename 安全性。本批是本地源码里程碑。

## 复现与修复

原产品将 `class C { function C(int $value) { ... } } new C(7)` 改名为 `D` 时，只修改类声明与类型引用，留下原方法 `C()`。实际 PHP 7.2 的对象属性从 `7` 变成 `unset`，命令仍成功退出；PHP 8.5 对照中该同名方法原本就是普通方法，两次都是 `unset`。这是构造行为的静默变化，不是索引等待。

当前工作区已有的 PHP 版本权威继续决定旧式构造。直接声明会联动类名、构造方法及可证明的方法族、直接调用、动态方法名和 callable 数组。有效旧式构造声明的 Rename 入口转到类型 Rename，继续使用原 PSR-4 文件名联动、预览、取消和 Undo/Redo。PHP 8、命名空间内的同名普通方法、现代构造优先与继承的其他名称构造保持原含义。

类本地的 Trait 构造别名按既有安全别名流程联动。共享 Trait 的原方法保留，通过当前类的精确 `use` 语法节点增加一个带原可见性的本地别名；其他消费者及原方法调用保持。已有 adaptations、嵌套 Trait、precedence、注释、Unicode 和 CRLF 均有核验。相邻的 `C as other` 原方法名曾误入类型引用，现已区分 Trait 类型来源／排除目标和方法／别名，避免编译失败。

PHP 7 的计划在独立语义 fork 中核对受影响类及其来源图：重命名前后须保持同一构造源码身份及可见性等属性。目的名称启用不同构造、静态旧式构造、名称冲突、不完整来源或独立方法 Rename 丢失原构造时，不返回可应用的计划。共享 Trait、父类等未编辑的依赖也进入既有源码哈希保护；其源码在生成计划后变化会使预览前检查失败，不修改用户文件。

这不是所有动态字符串、反射或不完整项目的 Rename 支持。原方法／别名流程不能证明的调用继续保守拒绝；多个顶层 Trait 无法唯一归属时也不猜测别名目标。未增加配置，标准 LSP WorkspaceEdit 保持，缓存事实合同仍为 87／5；本轮没有修改解析器、依赖或扩展版本。
