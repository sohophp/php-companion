# C3：Safe Rename 应用后的结果核对

日期：2026-09-26。仅修改 SoPHP Core 与隔离 C3 测试；未修改业务项目，未打包 VSIX。

## 问题与修改

Safe Rename 已有预览、来源快照和应用前复核，但应用阶段直接相信 `vscode.workspace.applyEdit` 的返回值。资源编辑可能已全部完成，调用却返回 `false` 或随后抛错；此时命令会把实际成功的改名报告成失败。

现在只有在应用调用报告失败时，才读取全部预期结果：核对每个参与文件的完整文本；若改名包含文件移动，还要求目标文件存在、旧路径消失。至少一处文本确有变化，或发生了预期文件移动，才能认定成功。任何缺失或部分应用仍按失败处理。正常返回成功的路径不增加额外文件读取。

## 验证

- 隔离 VS Code 1.139.1 Linux x64 的完整 C3 源码宿主退出码 0，日志 `/tmp/sophp-c3-rename-apply-outcome-20260926.log`。
- 本地变量改名覆盖应用后返回 `false`、应用后抛错、未应用返回 `false`、未应用抛错；命令结果与文本一致，已应用的两项各通过一次 Undo/Redo。
- PSR-4 类文件移动与跨文件使用方更新在应用完成后模拟 `false`，命令返回成功；旧文件消失，新类与使用方内容正确，一次 Undo/Redo 通过。
- 根扩展和 C3 测试 TypeScript、改动文件 ESLint 通过。

此证据只覆盖 Linux 源码宿主和上述完整应用、完全未应用场景。部分应用仍返回失败并保留现有失败提示；安装候选、真实 WSL Remote 和其它平台由 C4 验收。
