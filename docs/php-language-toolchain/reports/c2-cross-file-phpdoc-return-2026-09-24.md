# C2 跨文件 PHPDoc 返回类型编辑链

日期：2026-09-24。独立两文件 Composer 项目中，`records()` 的 PHPDoc 返回值从 `list<Alpha>` 未保存地改为 `list<Beta>`；已打开的使用方保持文档版本 1，执行成员补全、Definition 和参数类型诊断查询。测试使用 PHP 8.5 的真实 stdio，分别运行完整索引与默认 `onDemand`，没有修改业务项目或打包 VSIX。

声明文件打开期间，两种模式的成员补全均从 `onlyAlpha` 切到 `onlyBeta`，原 `onlyAlpha()` Definition 清空。完整索引下，使用方把元素传给 `acceptBeta(Beta)` 的诊断随修改从有变无；关闭未保存的声明文件后恢复磁盘上的 `list<Alpha>`，诊断和补全随之恢复。默认 `onDemand` 没有完整项目证明，因此使用方不发布跨文件参数类型错误；此前已打开的声明文件一旦关闭，Core 会直接丢弃该文件事实，使补全变空。

现在 `onDemand` 在关闭文件时读取磁盘内容，保留近期已关闭 PHP 文件的语义快照。每个 Composer 根最多保留 256 份，单文件还遵守项目索引的大小上限；重新打开会移出关闭缓存，文件监视变化会用磁盘新内容替换快照，删除或根移除会清理旧内容。定向 stdio 验证了未保存 Beta 关闭后恢复 Alpha、磁盘 `Alpha → Beta → Alpha` 两次 watcher 更新，以及删除磁盘文件后不再提供旧成员。此缓存改善近期使用过的声明文件；超过上限的较早文件仍需后续按需发现或重新打开，不据此宣称完整项目索引。

验证：Language Server 全套 18 个测试文件、332 项通过、1 项按原设置跳过；最终源码重新构建后，新增两种模式的定向 stdio 用例均通过。VS Code 1.139.0 隔离 Core 源码宿主在默认 `onDemand` 下，实际观察到两个已打开文件间未保存的 `Alpha → Beta` 返回类型切换，使用方补全随之变化、旧 Definition 撤销；原有 `never` 快速编辑与同文件参数诊断往返也通过，宿主退出码 0。相关 TypeScript、ESLint 与差异检查通过。该宿主没有覆盖关闭文件后的 UI 操作；其磁盘恢复与 watcher 行为由真实 stdio 证明。跨文件诊断在 `onDemand` 下继续保持未知；要报告确定的跨文件错误，仍需证明声明唯一、类型关系和依赖覆盖。其它 PHP 版本、Remote 与长会话留在 C4 门槛。

后续定向回归增加了使用方版本 2/3 的连续未保存编辑：声明已切到 `list<Beta>` 后，版本 3 的诊断和补全仍使用 Beta，版本 3 发布后没有迟到的版本 2 诊断。另一个真实 stdio 用例在默认 `onDemand` 下紧接着关闭、重新打开同一文件；关闭回调完成磁盘恢复时会先确认文件仍处于关闭状态，避免清掉新版本的诊断。两种索引模式的跨文件用例及重开用例共 3 项通过；Language Server 构建、类型检查、相关 ESLint 与差异检查通过。本轮没有运行完整 Pack 宿主或重新打包 VSIX，也不把短时序测试视为数小时长会话验收。
