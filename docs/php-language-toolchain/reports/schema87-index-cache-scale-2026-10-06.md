## 基准修复及验证

两脚本将最终 RSS 判定和报告移至清理之后，采用整进程高水位；持久缓存脚本新增内存预算结果并在超限时退出 1。数值显示允许四舍五入，门槛使用原始数值，预算保持。保留原阶段采样，索引报告补充每轮原始时长与首次回调的准确含义。

真实 1k 索引／缓存 CLI 冒烟分别退出 0，原恢复／损坏断言保持。仅验证门槛的隔离工具向 `resourceUsage` 注入 **384 MiB + 1 KiB**：两 CLI 显示四舍五入为 384.0 MiB，仍分别退出 1。注入不是产品测量；这四项只证明报告和退出门槛，没有把 10k／50k 原失败改写为新脚本通过。两脚本 Node 语法、ESLint、diff 检查通过，编译产品摘要保持。
