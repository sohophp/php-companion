# 属性赋值位置的预期类型补全

日期：2026-10-01。属于已批准补全专项的预期类型排序与可证明值建议。

## 复现与修改

原实现只在实参、返回和简单局部变量赋值取得预期类型。`$this->text = propertyValue` 的 string 属性候选仍按名称排序，int 函数排在 string 函数之前；bool 属性写入 `tr` 也没有 true 值建议。先建立失败回归，再扩充现有 expectedVariableCompletionType。

现在支持简单实例属性与静态属性赋值，包括已证明类型的参数接收者。复用现有唯一成员解析、完整继承链、可访问写入权限、writeType 和 PHPDoc 类型关系；函数返回、变量、常量、new 类型以及既有字面量／数组 shape 路径共用预期类型，不新增候选通道或产品设置。未知类型候选仍保留，兼容候选优先，不用类型匹配删除建议。

普通属性的相邻 @var 只有与写入合同可证明兼容，且成员来源唯一时才细化字面量建议。Hook 使用 setter 写入类型，不把 getter 的 @var 当成 setter 限制。联合接收者有多个不同 PHPDoc 声明时不选择其中一份；不可访问属性、未知接收者、只读属性不提供此项类型排序。只读属性初始化上下文、复杂链式／动态赋值不在这次新增范围，继续使用原补全；不把这些场景标为完成。
