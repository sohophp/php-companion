## 下一步的实质性检查

目前磁盘缓存保存了解析和语义事实，Reload 后首次查询仍须恢复大量文件并执行精确匹配。需要验证“持久化查询结果 + 完整输入校验”能否缩短这一条首次路径，而不是继续堆叠无明显收益的局部缓存。

验证/实现必须满足以下边界：

1. 区分空缓存首次与 Reload 后首次，分别报告；Reload 加速不能冒充空缓存加速。
2. 复用前证明项目候选集合与内容、查询文档/位置/是否包含声明、PHP 目标与配置、已消费依赖文件均未变化。新增、删除、移动、未保存编辑和 vendor 变化均须覆盖。
3. 动态 Provider、框架贡献或覆盖范围无法复核时，回退原语义路径，不把旧结果当作当前完整结果。
4. 取消、并发编辑、缓存损坏、版本/schema 不符必须安全回退；缓存不能覆盖新文档状态或产生错误的零引用。
5. 用完全相同的完整位置摘要，以及编辑/删除/移动后的新预期位置验证；性能验收使用正式 bundle 的独立进程查询。
6. 空缓存候选准备仍是独立剩余问题；不得为了缓存命中率忽略它。
