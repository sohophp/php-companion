# D137 Composer 根查找与删除／恢复

## 复现与源码修复

D136 的项目代次从根查找结束后开始，尚未保护查找本身。新增受控复现发现：已删除嵌套 Composer 的迟到根查找会恢复旧项目；旧目录根查找还会取得较新的项目代次，取消已经开始的新文档探测。新增两项均失败，原十项及另一嵌套项目的独立查找通过（11／13）。

在目录和文档查找开始时记录代次，返回后先检查同一 Composer 根是否已发生新通知或探测，再申请发布资格。其它 Composer 根的通知不撤销此查找。不改变版本解析优先级，也不修改业务项目。

自动版本源码宿主进一步发现状态栏错误：嵌套 Composer 从 8.5 改成 8.1 后删除，界面仍显示 8.1。独立单元证明内部已回到父项目 8.5，而缓存返回路径没有 render；补充此路径的状态栏刷新。对应单元从 13／14 到全部通过。

## 验证

- 最终根扩展完整单元：20 文件／107 项通过，零失败或跳过，其中版本协调 14 项。删除根、迟到根查找、异步版本探测、即时通知、嵌套独立性、目录移除及 dispose 均有具体反例。
- 根 TypeScript、宿主 TypeScript、变更文件 ESLint、production bundle 通过。初次新增状态栏 mock 的两个方法缺显式返回类型，Lint 失败；补注解后重新跑完整根单元及 Lint，通过。失败记录保留。
- Linux VS Code 1.140.0 自动模式 C1 宿主首轮退出 1，卡在删除嵌套 Composer 后状态栏仍为 8.1；没有跳过该操作。修复后第二轮完整运行退出 0，日志明确记录 `8.1 → 删除后父项目 8.5 → 恢复 8.1 → 还原 8.5`。Composer 自动版本、跨根设置／platform、嵌套查询及移除根执行；最终八项源码／产物／runner 输入哈希不变。

- `dist/language-server.js` SHA256 保持 D135 的 `2a3ff3766f3ae9d0ca998b7ec27f5ed5cec0770215001393cc401b74e5158a84`；本批修改扩展协调，不将旧 D134 的完整 LSP 结果转移为当前完整资格。
