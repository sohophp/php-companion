# SoPHP Symfony Rename 的打开文件与磁盘快照

日期：2026-09-25。独立 Symfony 扩展原先在返回跨文件 Rename 编辑前核对打开缓冲区和服务器来源摘要，但没有核对打开文件背后的磁盘。外部程序若在未保存 XML/YAML 缓冲区背后改写文件，旧编辑仍可能返回。根扩展的框架文档快照收集此前没有过滤工作区外的 YAML/XML；服务器要求每个快照都属于工作区，一项不符合就拒绝整批。下述修复前后对照支持这是未保存 XML 未进入服务器快照表的原因；本轮未逐个记录当时的工作区外 URI。

现在客户端只发送工作区内的 `file`/`vscode-remote` YAML/XML 快照。Symfony 扩展在请求 Rename 前记录已打开且未保存文件的磁盘摘要；返回编辑前，参与文件须同时满足服务器的缓冲区来源摘要，以及磁盘未被独立改写。已打开但干净的参与文件直接核对磁盘与服务器摘要；关闭文件继续核对当前磁盘与服务器摘要。磁盘不可读时拒绝返回编辑，并使用已本地化的来源变化提示。

隔离 VS Code 1.139.0 Linux x64 C3 宿主先复现了未保存 XML 的服务器计划仍使用旧磁盘摘要：缓冲区摘要 `d92ba283…`、磁盘和计划摘要均为 `483a2002…`。过滤工作区外文档后，同一宿主看到服务器快照变为缓冲区摘要；正常脏文件 Rename 计划可生成。随后暂停服务器已算出的计划，外部改写 XML 磁盘，再释放请求：Rename 拒绝旧编辑，未保存缓冲区与外部磁盘内容均保留。修复后日志 `/tmp/sophp-c3-symfony-snapshot-filter-20260925.log` 退出码 0。当前 10 项 Pack 的源码宿主正常 Symfony 跨 YAML/XML/PHP Rename 链也通过；快照过滤前后分别为 `/tmp/sophp-pack10-symfony-rename-disk-20260925.log` 和 `/tmp/sophp-pack10-symfony-snapshot-final-20260925.log`，均退出码 0。全程没有生成 VSIX。

Symfony 扩展单元测试覆盖干净文件外部写盘，以及未保存文件磁盘稳定/被改写两面；9 项通过。根扩展、Language Server 与测试的类型检查、相关 ESLint 和差异检查通过。此处是源码与隔离宿主证据；安装候选、WSL Remote 和真实用户的文件冲突提示仍待 C4 验收。未修改业务项目，也未打包 VSIX。
