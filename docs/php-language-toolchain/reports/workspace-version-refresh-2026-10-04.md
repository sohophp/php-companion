# Workspace PHP 版本刷新失效保护

## 可复现缺口

VersionManager 的全局、单目录和文档解析都包含异步 Composer／CLI 探测。旧结果没有代次检查，可能在较新的刷新之后完成。新增受控 Promise 回归在修复前精确复现两种失败：新版本 8.5 被旧版本 7.2 覆盖；已移除的 Workspace 根重新出现在版本状态中。

## 源码修复

为各 Workspace 目录保存刷新代次，全局刷新使旧代次失效，单目录刷新只使该目录失效。发布结果前验证代次、目录是否仍存在及对象是否已经 dispose。文档解析也遵循同一约束；旧刷新结束后不再为过期目录继续解析打开文档。停止后的迟到结果不触发状态事件或重新显示状态栏。

现有 Composer watcher 的局部刷新范围保持原样，不因一个嵌套项目的文件通知使整个父目录刷新失效。不修改 PHP 自动解析优先级、默认可执行文件、用户 Workspace 设置或业务源码。

## 证据范围

- 五个受控交错单元场景：旧全局刷新晚于新单目录刷新、移除目录、旧文档解析晚于新刷新、另一根的有效刷新保持、dispose 后迟到结果。初始两个红例均证明真实状态错误；修复后五例通过。
- 现有定向 LSP：热切换 PHP 版本／内建符号，以及 experimental／onDemand 两种嵌套 Composer 根，共 3 项通过、440 项未选中，13.42 秒。
- 根目录及隔离宿主 TypeScript noEmit、最终 ESLint 和 production bundle 通过。
- 最终源码 Core C1 隔离 VS Code 1.140.0 宿主退出 0：PHP 8.5，六类编辑查询在未保存接收者修改前后正常，Composer vendor、多根及嵌套版本／设置变更、移除目录状态通过。初次补全 102 ms；每类 12 次热命令采样中补全最大 10 ms、引用最大 76 ms。这不是长期性能预算或真实 WSL 状态栏验收。
- 宿主完整临时日志为 `/tmp/sophp-version-refresh-c1-final-20261004.log`。首次宿主运行通过后，审查移除了不必要的 Composer watcher 全目录代次变更；最终源码重新跑宿主通过。新测试的 return type lint 错误已修正，未以中间运行替代最终结果。

没有打包、更新 Profile 或推送；受控交错测试与隔离宿主不能代替真实 WSL Workspace 的持续使用。
