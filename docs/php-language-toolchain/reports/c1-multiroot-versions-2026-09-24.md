# C1 多根项目的 PHP 版本隔离

日期：2026-09-24。此前双根 Composer 工作区已隔离同名符号的六项查询，但语言服务器把 PHP 目标版本作为全局值。两个根分别配置 PHP 7.2 与 8.5 时，第二根的版本诊断、内建符号与缓存可能使用首根的版本。

扩展启动时现在传递每个工作区根的 PHP 版本；服务器按查询文件所属的 Composer 根取版本。版本用于内建符号、文档诊断、符号解析、代码操作、框架 Provider 请求、项目索引缓存与 References 缓存。内建符号的失效签名包含版本。根目录配置在会话中变化时，扩展会重新启动语言服务器，让新设置和打开的文档一起重新加载。

真实 stdio 的 F04-NAV-14 在同一会话中给首根 PHP 7.2、第二根 PHP 8.5：首根对 `enum`、`match`、`(void)` 报版本诊断，第二根没有这些诊断；`str_contains` 仅在第二根的内建补全出现。两根相同 FQCN 的六项编辑查询及首根未保存修改后的隔离仍通过。隔离 VS Code Core 宿主在 auto、7.2、8.1、8.5 设置下通过；三个显式版本用例给第二根设置不同版本，并在打开文件后再次更改第二根设置，诊断随新设置更新。7.2 与 8.1 宿主还复测了设置变更后的 `str_contains` 补全。TypeScript、ESLint、定向 stdio 和 Language Server 全套测试通过；全套为 305 项通过、1 项跳过。

目前 `auto` 在语言服务器初始化中仍按 8.5 回退；Composer 约束或运行时探测结果尚未作为每根的目标版本送入服务器。真实建议列表显示时间、完整 Open Source Pack、Remote 和持续使用也未由本报告证明。未修改业务项目，未打包 VSIX。
