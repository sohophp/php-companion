# D66 类型读取中的当前缓冲区保护

日期：2026-10-05。基线 `b1ad9ddd`，同一开发分支。

## 复现与修改

真实生产 bundle 查询 `use RootCand|`，暂停目标类型文件的 `readFile`。此时打开目标并改变未保存类名，旧读取结束后仍返回磁盘上的 RootCandidate。语义加载在 await 之前选择了文档，读取后直接把旧文本按“已打开文件”写入工作区，覆盖了缓冲区事实。

修复三处共享类型加载入口：PSR-4／直接已知类型、classmap／files／PSR-0，以及 classmap 命名空间候选。读取结束后重新取得当前文档与文本；PSR-0 的解析器准备提前进行，选择最新文本后到解析／更新之间不增加异步等待。当前 buffer 优先，原大小、数量、解析和路径可加载规则保留。

测试暂停仅在自己启动的独立子进程，通过已有读取门控实现，不改动安装扩展、用户项目或运行中的宿主。

## 原失败与测试修正

- 原生产输入明确返回旧类；改为同名接口反例后，按 `b1ad9ddd` Git 源码单独编译的旧服务器也明确返回旧 kind 7。该隔离构建有独立测试 engine 标识与显式 WASM 路径，不能当作旧正式 bundle 或性能样本。
- 首次扩展 PSR-0 用改类名但不改文件名，期望新类仍可加载，实际为空。该输入违反已有 PSR-0 路径规则；保留失败，改为同名类转接口，检验内容时序而不要求放宽 Composer 规则。
- 原父类门控把 final 删除后，修复后的旧请求能返回当前合法构造候选，却与原“必须为空”断言冲突。原测试把旧磁盘 final 导致的空列表误认为依赖请求失效证据。强化为相反方向：未保存父类增加 final，仍要求旧结果为空且新查询禁用构造；旧源码明确失败，当前源码通过。没有删除取消、编辑或宽前缀恢复断言。
