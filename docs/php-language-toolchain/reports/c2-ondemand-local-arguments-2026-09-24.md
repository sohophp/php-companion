# C2 按需模式的同文件参数诊断

日期：2026-09-24。Open Source Pack 默认使用 `onDemand`，完整项目索引尚未建立时，语言服务器原本只发布语法、文件名和少数局部诊断；即使函数或方法的唯一声明和调用位于同一个打开文件，明确的缺少参数与参数类型错误也被完整索引门槛挡住。独立 stdio 反例中，严格类型的本地 `int` 参数收到字符串，旧结果没有 `php.argument.type-mismatch` 或 `php.argument.missing-required`。

现在语义查询在索引不完整时只接受**声明 URI 与调用 URI 相同**的签名。函数和方法都要求已加载声明唯一；展开参数、动态或无法确定的签名仍遵守原有保守规则。跨文件签名即使碰巧已被另一个打开文件加载，也不能在 `onDemand` 下据此发布参数错误。索引已证明完整时，原有跨文件诊断范围保持不变。

真实 stdio 在 PHP 7.2 和 8.5 都验证了同文件函数的缺少参数及函数/方法的字符串传给 `int`，并验证未保存修复后错误消失；另一个已打开文件中的 `external(int)` 调用不产生未证明的跨文件类型诊断。隔离 VS Code 1.139.0 的默认 `onDemand` 宿主在独立临时夹具中看到 3 条参数错误，未保存修复后变为 0 条；原有 `never` 快速编辑往返仍通过。源码构建、定向语义和 stdio 测试、ESLint 与差异检查通过。

完整源码 Extension Host 首轮在 DynamicProperties 的 Undo 后等待 5 秒未收到预期的 4 条 `AllowDynamicProperties` 诊断，尚不能确定成因。为该断言增加文档版本与诊断快照、等待上限改为 10 秒后，完整套件复测以退出码 0 通过；这只证明复测通过，偶发等待仍须在后续长会话观察。

这项证据覆盖明确的同文件签名，不意味着默认 `onDemand` 已能安全报告所有跨文件参数类型错误、动态 PHP 或不完整依赖树中的问题。此次只修改 SoPHP 仓库及临时夹具，不修改 Winstar 或其它业务项目，也不为源码增量打包 VSIX。
