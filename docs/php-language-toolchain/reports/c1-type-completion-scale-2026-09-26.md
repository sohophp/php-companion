# C1 项目类名补全的声明遍历成本

日期：2026-09-26。只在 SoPHP 内存语义工作区建立独立短 PHP 文件；未修改业务项目，未打包 VSIX。

## 发现与修改

原 `completeTypes` 每次查询都扫描全部文件声明，并对**每个候选**重新遍历可见名称、逐文件寻找声明所属 URI。3,001 文件、同一 namespace、输入 `new Type29` 的本机 20 轮热查询中位约 **816 ms**、P95 约 **877 ms**，目标类在结果中。该单函数等待已经足以影响编辑器交互。

现在一次构建类声明及其所属文件映射、导入别名和反向可见名称；类导入别名只从 `use` 类导入读取，避免同 FQCN 的 `use function` 抢走类名标签。每个已解析文件的声明命名空间再按声明数组引用缓存，编辑后换数组时重建该文件的元数据。用户可见结果继续按原有可见性、namespace 邻近度和名称排序。

新增 [`benchmark-type-completion.mjs`](../../../scripts/benchmark-type-completion.mjs) 复现入口：构建 parser 与 semantic 包后，运行 `node scripts/benchmark-type-completion.mjs 3000 20`；参数也可设为 `10000 20` 或 `50000 20`。脚本检查目标类存在，并输出文件创建时间、热查询中位、最近秩 P95 和最大值。

| 阶段 | 文件数 | 热查询次数 | 中位 ms | P95 ms |
| --- | ---: | ---: | ---: | ---: |
| 原始逐候选遍历 | 3,001 | 20 | 815.5 | 876.8 |
| 单次映射 | 3,001 | 20 | 4.3 | 9.3 |
| 单次映射 | 10,001 | 20 | 19.6 | 31.6 |
| 单次映射 | 50,001 | 5 | 152.5 | 176.0 |
| 加按文件声明元数据缓存 | 50,001 | 20 | 121.6 | 136.1 |
| 仅按候选查询可见名称 | 50,001 | 20 | 63.4 | 80.3 |

最后一步不再为全部同 namespace 类建立可见名称和反向名称表；只对实际匹配的候选检查本地声明与导入冲突。以上是同机进程内语义函数时间，前后轮数不完全一致，也未测内存峰值；不能当作协议往返或正式 R1 的 50k/100 轮门槛。50k 查询仍遍历已加载声明，后续需验证连续输入后的完整协议往返、100 轮 P95、取消响应及内存预算。

Semantic 全量 346 项通过，新增同 FQCN 函数/类导入断言验证只返回正确类别名；根 TypeScript、相关 ESLint 与差异检查通过。独立 VS Code 1.139.0 Linux Core 源码宿主中，新增项目类名补全断言与原有六项编辑查询、vendor、多根链通过。单次映射版日志 `/tmp/sophp-c1-type-completion-name-host-20260926.log`；按文件缓存版日志 `/tmp/sophp-c1-type-completion-cache-host-20260926.log`；最终按候选可见名称版重新构建后的日志 `/tmp/sophp-c1-type-completion-50k-final-host-20260926.log`，三次均以 0 退出。这是隔离源码宿主证据，不是已安装 VSIX、真实 WSL Remote 或长期使用验收。
