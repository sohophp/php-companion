# D159：Trait 关键字预检与普通编辑成本

## 修改与同输入对照

基于 `3d35199c`。当前正式产物的独立 PHP 7.2 CPU 采样发现，Trait precedence 恢复前的全文 Unicode 正则累计约 505.51 ms。Source map 正文与被采样 bundle `426850aa` 逐字节一致；采样时间不作为普通性能结果。

两种不同方案各测一次：直接查询真实 token 未证明 PHP 7.2 P95 改善，已撤回；最终保留 ASCII 不区分大小写的子串预检，命中后仍由真实 `insteadof` token 和原完整恢复规则判断。当前 Tree-sitter grammar 的关键字定义同样使用无 `u` 的 `/i`。宽松预检可以多做一次检查，不从字符串、注释或名称猜测 Trait 子句。

沿用 D74／D100 的同一 242801 字节、1500 注释／常量夹具，哈希 `7c2b86d10cc3ab037eb5ad5704287c25460da3f3fc2f63c63d9f7b068c5aa479`。每实现、每 PHP 版本一次串行 100 轮未保存修改后立即补全，首项、共享候选、磁盘原文保持；普通测量没有 CPU profiler、显式 GC 或 RSS 采集。

| 实现 | PHP 7.2 P50／P95／最大 | PHP 8.5 P50／P95／最大 |
| --- | ---: | ---: |
| 当前基线 | 117.53／160.22／237.68 ms | 114.87／154.09／224.02 ms |
| 直接 native token 查询，已撤回 | 104.37／163.56／263.69 ms | 112.42／147.16／449.78 ms |

最终两组低于原 150 ms 门槛。仅关闭这个固定夹具的本次超限，不证明所有普通项目、规模或长会话性能达标，也不把不同历史批次拼成改善结论。直接查询方案启动初期与限定 ESLint 有重叠，该组不作为资格证据，没有重测挑选绿色；最终 ASCII 组在独立检查结束后执行。
