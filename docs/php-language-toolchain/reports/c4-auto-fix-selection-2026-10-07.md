## 实际问题与修复

补齐真实括号自动格式化延迟用例后，原 Windows 完整入口在“CLI 等待期间只改变选区”失败：文档版本没有变化，旧结果仍被应用。原有版本／焦点保护没有覆盖用户选区。继续输入、切换文件的两个新增括号用例在同一原失败进程中通过，失败本身保留。

候选在括号和分号自动修复请求中记录全部选区的 anchor／active 坐标；实际 CLI 返回后，选区变化则丢弃结果。普通手动格式化保持原入口，未新增配置。

第一版直接记录分号事件当时的选区，被原正常正例拦截：文档变更通知早于输入命令的正常光标移动，因此误拒绝当前结果。该 `bb3030e3` 原型已撤回。最终候选把分号触发的实际文本变更映射到预期选区，区分正常输入与后续手动选择；括号请求在 `cursorUndo` 恢复光标后记录选区。

模拟夹具也据此补齐输入完成后的光标移动。原 20 个边界保留，新增单选区／多光标变化和三项选区坐标用例，共 27 项通过。UTF-16、多点同时插入、跨行替换只具有该定向证据，不称为真实多光标 UI 验收。
