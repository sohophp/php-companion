## 原问题与修正

- 六个现有 64 位 PHP CLI（7.2／7.4／8.1／8.2／8.4／8.5）的原 376 条有效原生观察，对应返回／输出、字面量／简单局部变量及保留／丢弃树的 3,008 场景；旧产品 2,032 一致、976 不一致。其中已知非数值字符串被宽泛弱兼容判断放行，严格模式整数到浮点转换的条件结果也不准确。
- 独立模块建模原生参数边界，保留精确原生类型、严格模式整数到浮点例外、数值字符串规则、PHP 7 数值前缀行为及 Union 的转换选择。未知字符串不被当作已知非法字符串；未指定目标版本时保留 PHP 7／8 差异。
- 单独保存浮点字面量来源：`42.0`、`1e3`、`42.` 不因 JavaScript 值为整数而变成 PHP 整数；条件判断不再把原始浮点类型当作整数子类型。
- 简单局部值仅沿同块稳定赋值证明；引用、分支、调用及同一表达式中较早使用／修改该变量时保守回退。六个运行时确认：先按值传入非法字符串、随后实参修改变量，前一个值仍非法；先修改再读取变量则合法。原错误安全断言已更正，原证据保留。
- 更精确的字面量重载选择新增两条真实返回错误：数组返回给 `string`、非数值字符串返回给严格 `int`。原回归断言增加两条错误，六 CLI 的 12 次返回控制均拒绝；没有通过删掉诊断换取绿色。
- 新协议矩阵发现四个首次条件返回请求为空。声明依赖原来只取得直接单一返回类；现按唯一具名函数的返回注解收集条件分支中类的源码，复用原有 Composer 定向加载、限额和取消检查。依赖不选择条件分支，也不作为变量值证明。
