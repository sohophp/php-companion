# C2 路径仓库符号链接的未保存编辑与文件监视

日期：2026-09-24。用独立临时 Composer 项目模拟 `packages/local` 路径仓库及 `vendor/local/package` 符号链接，运行默认 `onDemand` 的真实 Language Server stdio；没有修改业务项目或打包 VSIX。

## 用户可见场景

从包的真实路径打开 `Record.php`，未保存地把 `alphaOnly()` 改成 `betaOnly()`，项目使用方的成员补全须显示 Beta；关闭后须恢复磁盘 Alpha。随后磁盘改成 Beta，监视器从安装链接 URI 通知；再从真实路径打开未保存 Alpha，链接 URI 的监视通知仍须遵守打开缓冲区；关闭后恢复磁盘 Beta。最后由真实路径通知 `gammaOnly()` 更新，再从链接 URI 通知删除，不能留下旧成员。

新用例先复现了一个错误：链接 URI 的磁盘通知更新了新事实，但真实路径的近期关闭快照仍保留旧 Alpha，使用方继续显示 Alpha。测试也发现从真实路径来的监视通知原被字面的 Composer autoload 目录判断丢弃，因为 autoload 目录是 `vendor` 下的链接。

现在 watcher 对路径仓库同时核对字面路径和物理路径；物理路径匹配后仍用安装路径检查 Composer 排除规则。应用文件变化时，优先读取同一物理文件的打开缓冲区，并撤下其它 URI 中过期的已关闭或已索引事实；文件已删除时通过父目录解析链接归属。若文件读入期间新增嵌套 Composer 根，应用前再核对根归属并重排事件。打开和修改回调在异步根发现或磁盘读取后，也会检查文档仍是当前版本，避免迟到的回调重新写入旧内容。

真实 stdio 新场景包含 10 次额外开关往返，链接与真实路径的监视更新、打开缓冲区优先及删除清理均通过；单用例独立重复 5 次均通过。嵌套根、安装 vendor、路径仓库及跨文件 PHPDoc 的相关回归共 11 项通过。完整 Language Server 套件 18 文件、336 项通过、1 项跳过；类型检查、相关 ESLint 与差异检查通过。当前只验证一个打开的物理文件缓冲区；同一文件经两个 URI 同时打开并发生互相冲突的未保存编辑、Windows/macOS 实际宿主、完整 Open Source Pack 与数小时使用，仍待单独验收。
