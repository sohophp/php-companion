# References 输入验证：减少重复核对并处理时间戳碰撞

日期：2026-09-22。基线：`ddb5e89`。Winstar 仅作只读测量，未改应用代码或安装版 VSIX。

## 撤回后台候选缓存写入实验

空缓存采样仍指向候选扫描约 5.4 秒、语义计算约 2.7 秒。关闭缓存写入的独立样本仍需 8.860 秒，因此写入不是主要瓶颈。

本轮曾试验把候选缓存提交移到后台，按缓存路径串行写入、正常退出时等待完成，再增加分块 JSON 写入以避免阻塞随后导航。三组实际正式 bundle 对照如下，均为 2,289 个候选文件、112 处引用，全部位置摘要一致：

| 对照 | 原版 References / Definition | 实验版 References / Definition |
| --- | --- | --- |
| 先原版后实验版 | 10,109 / 41 ms | 9,770 / 190 ms |
| 反向运行 | 9,410 / 41 ms | 9,230 / 186 ms |
| 分块写入，先实验版后原版 | 9,651 / 35 ms | 9,492 / 58 ms |

前两组将一部分等待转移到紧接着的 Definition；最后一组差异大部分来自语义计算波动，候选扫描为原版 5,247 ms、实验版 5,261 ms，未证明稳定的扫描收益。因此后台 API、写入队列、分块实现和专用用例全部撤回。实验期间索引 31 项、正式 stdio 3 项通过，不代表性能已达标。补丁只留在忽略目录 `node_modules/.cache/before-background-reference-write/experiment.patch` 供复查。

## 保留的输入验证改动

文件首次打开后记录描述符的设备、inode、大小、纳秒 mtime/ctime，按该大小有界读取并计算内容摘要。所有文件读取完成后再次检查完整文件集合，再逐路径与首次描述符状态比较。这轮最终检查已覆盖替换、增长、截断和状态变化，因此移除每个文件读取后紧接着的两次重复 stat。源码仍实际读取并计算摘要，没有改成仅凭 mtime 复用内容。

新增测试发现本机时间戳碰撞：20 次快速连续的同长度改写并恢复 mtime 中，19 次 ctimeNs 也相同。纳秒字段不代表底层时钟每次写入都递增，重复 stat 无法识别这类变化。

因此，首次读取时 mtime 或 ctime 位于捕获开始前两秒以内（含未来时间戳）的文件，在最终阶段额外有界重读并比较内容摘要，再核对状态。较旧文件保留最终身份/状态核对；它们的实际内容仍在首次读取阶段完整计算摘要。复核沿用每文件大小、并发和文件数限制；近期文件至多增加一轮有界内容读取。

## 缩短基准驱动器的退出等待

`benchmark-language-queries.mjs` 的退出处理使用五秒超时与进程退出事件竞争，但成功退出后未清除计时器。这个计时器让基准驱动器自身继续存活近五秒，每次冷启动+Reload 对照白等近十秒。

现在无论正常退出还是超时都会清理该计时器，原有五秒强制终止上限保持不变。隔离的合成 stdio 服务探针均返回两次合法查询响应，旧脚本整轮 5,134 ms，修改后 153 ms；这项数据仅证明驱动器退出开销，不能当成 PHP 查询耗时。

修改驱动器后，真实 Winstar 的冷查询→等待后台保存→退出→新进程恢复完整检查共 **14.39 秒**，包含两轮 References 与 Definition 校验。该轮 References 冷查询 8,908 ms、Reload 2,676 ms，均为 112 处完整位置一致；Definition 分别为 7/170 ms。冷查询波动不能当成本轮加速收益。

这项改动主要优化持久化 References 的输入验证，不代表空缓存候选扫描和语义计算已解决。完整 Symfony Profile、实际 WSL 编辑以及首次耗时目标继续保持开放。
