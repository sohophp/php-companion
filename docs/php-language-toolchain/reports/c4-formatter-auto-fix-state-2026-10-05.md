# D76：格式化候选的自动修复文档与版本保护

日期：2026-10-05。本批沿已有 C4 外部工具组合范围修补隔离的 `junstyle.php-cs-fixer 0.3.21` 开发候选；Core 不增加格式化器，用户 Profile、Marketplace 原版及默认配置没有更新。

## 复现与修复

原候选在分号／括号自动修复中使用当前活动编辑器，没有核对它是不是触发变化的文档。后台文档出现分号时，原候选实际调用另一文件的格式化；精确类边界回归取得 `1 !== 0` 的失败。CLI 返回后的回调也不核对版本，能够用旧片段替换随后输入。

候选现在要求活动编辑器属于事件文档且文档未关闭；捕获版本，在跳转括号、恢复光标和实际 CLI 返回后重新检查版本、关闭状态与焦点。失效后停止应用或继续移动光标。编辑返回失败或完成后焦点已变化时，不再执行另一个编辑器的 `cancelSelection`。正常当前文档的既有格式化算法和规则保持。

原版 bundle `0d94dba0…` 保持不变；上一个候选 `f19592bc…` 是本次失败的基线，新候选 SHA-256 为 `aa440f0e83294968d27a6f9f723a68173bd13bc7871ce1d70417e9f9bfe38068`。生成脚本继续锁定原始 bundle、全新目标和 ISC 许可，LICENSE.txt 逐字相同。
