# C1 可见补全等待归因

日期：2026-09-26。VS Code 1.139.0 Linux x64、独立临时 Composer 项目、SoPHP Core 源码宿主。未修改业务项目、Pack 默认值或 VSIX。

## VS Code 建议延迟 A/B/A

同一隔离宿主按“原默认值 10 ms → 工作区临时设为 0 ms → 恢复 10 ms”依次测试六个不同 PHP 类的键入补全。每次在编辑器缓冲区实际输入 `r`，Workbench DOM 观察器从命令提交前计时到可见建议行，并核对当前类的专属方法。三组均为 6/6 正确，宿主退出码 0；日志 `/tmp/sophp-c1-quick-delay-aba-20260926.log`。

| 设置 | 六次可见等待，毫秒 | 中位数 |
| --- | --- | ---: |
| 原默认 10 ms | 279、246、238、231、231、253 | 242 |
| 临时 0 ms | 232、224、243、236、248、249 | 240 |
| 恢复 10 ms | 274、261、266、264、252、260 | 263 |

零延迟组没有稳定且足以解释约 230–260 ms 可见等待的改善，故不修改 Open Source Pack 的编辑器默认值。顺序样本受缓存、Workbench 状态和计时抖动影响；它不证明设置在其它机器上完全无效。

## 输入通道对照

另一隔离宿主在原设置下先以 VS Code `type` 命令输入六个不同 PHP 类，再用 Chromium `Input.insertText` 直接向已聚焦的 Workbench 编辑器输入另六个类。两组均为 6/6 正确，宿主退出码 0；日志 `/tmp/sophp-c1-workbench-input-20260926.log`。

| 输入通道 | 六次可见等待，毫秒 | 中位数 |
| --- | --- | ---: |
| 扩展 `type` 命令 | 247、227、231、241、219、224 | 229 |
| Workbench 输入接口 | 244、245、259、224、255、237 | 245 |

直接向 Workbench 输入没有消除约 200 ms 级的等待，不能把先前结果归因于扩展测试命令跨进程调用。Chromium 输入接口仍不是物理键盘到屏幕像素的人工测量。两组都只有六个顺序样本，也没有在同一输入上分段测量 VS Code 调度、Provider 和 DOM 更新；不以此推断长期 P95 或修改 Core 补全触发机制。后续优先修复可复现的错误候选、旧结果和明显长尾，并在冻结候选的真实组合中记录可见体验。

## 同一次输入的阶段计时

在当前 10 项 Open Source Pack 源码组合中，DOM 观察器同时记录输入文本出现在 Monaco 编辑器与建议行可见的时刻；测试前清空语言服务器计时，再读取本组六次补全处理耗时。C1 隔离宿主完整退出码为 0，普通类与 vendor 类各 6/6 候选正确，10 轮快速切换未出现旧类型候选；日志 `/tmp/sophp-c1-visible-phase-20260926.log`。

| 阶段 | 六次样本，毫秒 | 中位数 |
| --- | --- | ---: |
| 输入出现在编辑器 | 43、44、34、30、42、88 | 43 |
| 建议行可见 | 276、231、259、256、252、262 | 258 |
| 输入显示后到建议可见 | 233、187、225、226、210、174 | 218 |
| 语言服务器补全处理 | 0.45、0.37、0.57、0.42、0.61、0.52 | 0.49 |

这组结果将约 200 毫秒的主要等待限定在编辑器已有输入之后、建议行可见之前；服务器本次补全计算不足 1 毫秒。这一轮尚未分别覆盖 VS Code 建议触发、语言客户端传输、Provider 返回和建议控件绘制；下节继续测量 Provider 边界。

## 语言客户端 Provider 边界

随后在同一 10 项 Pack 源码组合中，用测试开关记录 SoPHP 语言客户端补全 Provider 的入口与返回绝对时间，并与 Workbench 同次输入和建议列表时间对齐。完整 C1 宿主退出码 0；普通类、vendor 类各 6/6 候选正确，快速切换 10 轮没有旧类型候选；日志 `/tmp/sophp-c1-client-completion-phase-20260926.log`。

| 普通 PHP 补全阶段 | 六次样本，毫秒 | 中位数 |
| --- | --- | ---: |
| 编辑器显示输入 → SoPHP Provider 入口 | 93、87、91、83、89、88 | 89 |
| SoPHP Provider 入口 → 返回 | 3、17、4、18、4、3 | 4 |
| SoPHP Provider 返回 → 建议行可见 | 128、103、109、107、104、111 | 108 |
| 其中服务端实际补全计算 | 0.43、0.33、0.59、0.44、0.50、0.47 | 0.45 |

两段主要等待分别在 Provider 入口之前和返回之后。Provider 的 3–18 毫秒包含语言客户端传输与服务端处理；服务端计算仍不足 1 毫秒。跨进程绝对时间使用同一宿主机器的时间基准，数字适合定位本次阶段，但不是物理键盘到像素的测量，也不能代表其它机器或长期 P95。下一步若有新的可复现慢样本，应优先检查 VS Code 建议触发与列表呈现的条件；当前保持 SoPHP Core 逻辑和 Pack 默认设置。
