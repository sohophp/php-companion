# References 全候选读取证据及并行输入核对

日期：2026-09-22。上一基线：`f854c46`（产品代码 `c11784c`）。

## 解决的缺口

原输入审计核对语义工作区已经加载的文件，但一个被候选名称筛选跳过的文件如果在查询后新增调用，不会出现在已加载来源中。直接将当前输入快照配对到旧查询结果，可能漏掉这处新引用。

现在 `scanNamedCandidates()` 记录每个实际读入/恢复路径及摘要，包含判定跳过的文件。扫描完整、未取消、项目代次未改变、读取数量与扫描数量一致时才保留证据；新扫描开始即清除旧证据。记录上限 50,000 条，只保留每个工作区最近一次完整扫描，随工作区释放。

输入快照单独记录从源码根发现的文件集合，与明确请求的依赖/元数据区分。审计按相同 Composer 排除规则核对扫描集合与每个文件的磁盘摘要，额外依赖文件不能冒充源码集合成员。快照指纹升级到内部 schema 2，包含来源集合角色。

核对仍在测试专用审计路径中；没有启用缓存引用结果返回。最近一次扫描证据还不能代替某个查询结果的完整绑定，`semanticCoverageVerified` 保持 false。引擎构建身份、查询版本绑定、框架/Provider 输入与持久化结果格式仍需完成。

## 校验成本

原来逐个等待显式输入的 `realpath/stat`，现在每批最多并行 32 个。目录遍历也每批最多并行 32 个目录，文件和目录数量均有上限。

继续保留前后两次文件集合/链接目标检查、文件字节摘要、读取前后以及最终文件状态核对、取消检查和容量预算。嵌套符号链接或不完整读取仍拒绝核对，不用时间戳取代内容摘要。
