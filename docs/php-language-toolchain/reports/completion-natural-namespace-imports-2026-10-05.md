# D68 自然输入的命名空间导入

日期：2026-10-05。产品基线 `653b2e53`，产品源码和生产 bundle 未改变。本批增加可复用自然输入门禁。

## 工作流与证据

Linux VS Code 1.140.0、PHP 配置 8.5、onDemand，使用隔离 Composer PSR-4 项目，逐字 Workbench 输入；没有 `executeCompletionItemProvider` 预热或手动 `triggerSuggest`。

新增普通类型、分组、function、const 四类导入。从命名空间前缀接受 Module，继续输入嵌套段，再接受真实符号并填写别名。普通类型另改前缀、恢复前缀，核对旧类型撤回。各次 Enter 后核对整个文本及光标，Module 后光标必须在反斜杠之后，类型／函数／常量导入不插入调用括号。下一段符号必须在可见列表首位且恰好一次；别名位置要求列表隐藏并稳定观察 500 ms。

function／const 的声明来自第一条流程打开的单份源码目录，后续消费者引用它；本批不声称证明未打开函数库的首次发现，那仍由相应 Composer 协议单列。候选等待为自然键入后的可见列表观测，不是热 LSP 延迟，也不作为 150 ms 连续编辑预算通过。

## 原输入问题

首次整套宿主退出 0，但夹具在四份消费者中重复声明同一批函数／常量，可见列表包含重复定义，因此不将该结果作为有效项目验收。改为第一条消费者单次声明，后续消费者采用独立 namespace；加入最终符号唯一性断言，再完整运行 12 条流程通过。没有修改产品去重或排序规则。新直接访问由 helper 初始化的 document／editor 另补 TypeScript 确定赋值标注，工程门禁通过；标注不改变运行逻辑。

完整可见状态、接受文本、原始日志摘要及输入 SHA-256 见 [结构化证据](completion-natural-namespace-imports-2026-10-05.json)。
