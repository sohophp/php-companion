# C3：类型生成在资源移动后的结果判定

日期：2026-09-26。仅修改 SoPHP 源码与测试宿主；没有修改业务项目或打包 VSIX。

类型生成先把预览内容写入暂存文件，再通过 VS Code 资源编辑移动到目标。原实现仅按 `workspace.applyEdit()` 的返回值判定是否创建成功。如果移动已完成而调用随后返回 `false` 或抛错，命令会误报失败，甚至把已经存在的生成文件当作冲突。

现在资源编辑返回后检查暂存文件是否消失，以及目标文件在磁盘上的字节是否与预览内容一致。只有两项都成立才认定移动完成；未移动、目标内容不同或无法读取时继续走原有安全兜底。完整 C3 宿主分别注入“真实移动后返回 `false`”与“真实移动后抛错”，验证命令返回 `true`、文件内容正确，以及一次 Undo/Redo 恢复文件。

多工作区用例会使 VS Code 记住动态工作区。普通 C3 宿主现为每次运行使用独立用户数据目录，避免下一轮打开已清理的旧临时路径。第一次运行因旧用户数据恢复旧路径，在基线夹具处失败；隔离后复跑通过。TypeScript、定向 ESLint、`git diff --check` 与 VS Code 1.139.1 Linux x64 完整 C3 源码宿主均退出码 0；日志 `/tmp/sophp-c3-post-apply-result-isolated-20260926.log`。

最终 `createFile` 兜底的一次 Redo 缺口仍在；安装候选与真实 WSL Remote 尚未包含本次源码增量。
