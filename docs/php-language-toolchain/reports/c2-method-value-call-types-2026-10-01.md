# C2：明确目标的按值方法调用后保留局部类型

日期：2026-10-01。源码增量；未打包、Git 提交、推送、发布或更新 Profile。

## 复现与实现

`$value = null ?: new Repo(); $observer->observe($value); $value->rea` 在 observe 的目标和按值参数都可证明时仍丢失 ready 补全。既有普通函数调用证明没有覆盖方法语法，导致同一类型事实在补全和诊断中被不必要地撤回。

本轮把唯一函数的参数证明入口扩为 `knownCallHasOnlyValueParameters`，方法复用现有签名与声明解析：要求唯一实际声明、唯一接收者类，并以 final 类、final 方法或 private 方法证明目标不可被覆写；所有参数必须非引用。PHPDoc 魔术签名、动态未知目标、重复类和未证明的派发保持失败。

局部线性类型证明接受这些明确目标的实例、nullsafe 和静态方法调用，以及独立局部变量接收结果的调用。实参仍限制为直接变量或不插值的标量字面量；unpack、参数内赋值、复杂表达式和此前引用逃逸不放行。对象属性的稳定性判定不因此放宽；这里证明的是未逃逸局部绑定不被按引用重绑，并不是方法纯净或没有副作用。

方法解析可能再次查询局部类型，因此增加按调用键的重入保护与既有深度预算；失败保持 unknown。证明缓存继续按 sourceRevision 失效、上限 1024，不把旧方法参数用于未保存编辑后的查询。
