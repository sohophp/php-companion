# C3 未保存关联文件背后的外部磁盘变化

日期：2026-09-25。只修改 SoPHP 仓库与独立测试夹具；未修改业务项目，也未打包 VSIX。

## 问题与处理

Rename 和 Safe Move 的编辑计划可以包含已打开、尚未保存的关联 PHP 文件。此前两者会按缓冲区文本核对服务器计划；由于磁盘本来就与脏缓冲区不同，不会直接拿计划文本比磁盘。若外部进程恰在规划期间或计划返回后改写该文件，缓冲区仍保持旧内容，旧计划可能进入预览。修复前的 Rename 宿主负例确实触发“旧计划进入预览”的断言。

两条命令现在在规划开始前记录当前已打开且未保存文件的磁盘摘要；获得计划后，仅对该计划实际涉及的文件复核磁盘摘要。关联文件的未保存文本保持原样，外部磁盘变化使命令在预览前返回 `false`。已有的源文件版本、服务器源码快照及预览确认后的检查继续生效。

## 验证

隔离 VS Code 1.139.0 C3 源码宿主在两个独立场景中为关联文件保留未保存编辑，再于计划返回后外部改写同一磁盘文件。Rename 和 Safe Move 均未打开旧预览，未保存缓冲区与外部磁盘内容分别保留，源文件未改名或移动，目标路径不存在。同一宿主的正常预览、应用、一次 Undo/Redo 及其余 C3 序列通过，退出码 0；日志为 `/tmp/sophp-c3-dirty-related-disk-race-fixed-20260925.log`。根扩展与测试 TypeScript、改动文件 ESLint 和差异检查通过。

该宿主只覆盖可控的规划后改写时序；安装候选、WSL Remote、真实 Explorer 事件与长期使用仍需单独验收。生成新文件的一次 Redo 缺口保持开放。
