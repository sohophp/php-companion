# F02 版本语法诊断的隔离编辑器宿主复核

日期：2026-09-25。环境：Linux x64、缓存的 VS Code 1.139.0、隔离的 C1 Extension Host 与临时 Composer 工作区。Core 从当前源码加载；未生成 VSIX，也未修改业务项目。

现有 C1 三版本流程新增两个独立 PHP 文件。第一个在普通字符串与注释中放入 `|>`、`??=`，并在调用的尾随逗号之后放入注释；第二组分别以单类型文件测试 `public /* final */ string $name` 和真正的 `public final string $name`。宿主读取 VS Code Problems 中的 SoPHP 诊断，而不只调用分析函数。PHP 7.2 目标仅对实际尾随逗号及实际 final 修饰符报告对应版本错误，诊断范围分别为 `,` 和 `final`；8.1 目标不再报告尾随逗号，仍报告真实 final；8.5 目标均不报告。三者都未把字符串或注释内容误认成操作符或修饰符。现有六项编辑查询、未保存切换及多根流程在同一次宿主运行中继续通过。

| 设置 | 宿主结果与日志 |
| --- | --- |
| Composer `>=7.2` 的 auto 目标 | 完整 C1 宿主退出码 0；`/tmp/sophp-f02-version-host-auto-final-20260925.log` |
| 显式 PHP 8.1 | 完整 C1 宿主退出码 0；`/tmp/sophp-f02-version-host-81-final-20260925.log` |
| 显式 PHP 8.5 | 完整 C1 宿主退出码 0；`/tmp/sophp-f02-version-host-85-split-20260925.log` |

源码构建、测试入口 TypeScript、相关 ESLint 与差异检查通过。首次 7.2 和 8.5 宿主尝试因测试夹具等待“文件名不匹配”诊断而失败：合并文件含两个类型，不满足该诊断只检查单一主类型的条件；外部 PHP 校验还会报告旧运行时的语法错误。把注释反例和真实 final 正例拆成单类型文件后，上表三轮均通过。这是夹具就绪条件错误，不是 SoPHP 版本诊断回归。

此证据覆盖 Linux 源码宿主中的自动诊断展示，不代表已安装 VSIX、WSL Remote、其它平台或长期使用；F02 全部语法矩阵仍未完成。
