# 光标位置语法定位：减少无关子节点展开

日期：2026-10-12。范围为已有语义查询的局部定位性能；保持支持域、诊断、完成项、恢复边界及原遍历预算。

## 成本与实现

上一轮已否定“反复读取 getter 会反复创建数组”的假设。本轮检查的是另一条实际路径：`deepestLocalSyntax` 在定位单个光标位置时，旧遍历仍会读取包含节点的全部 `namedChildren`，创建大量随后被范围判断跳过的兄弟节点包装对象。

光标位置现通过有序兄弟节点的开始/结束位置二分查找，展开全部包含该位置的子节点；相邻节点共享边界时保留原从左到右的顺序和深度优先选择。跳过的兄弟节点以计数参与原100,000节点预算，原256层深度预算保持，包括超深的被跳过兄弟节点。非空范围与逆向恢复范围继续使用原路径。没有新增跨查询缓存或改变类型证明规则。

初版私有原型也将逆向范围放入二分路径，定位结果一致，但全范围展开的原生逐节点调用成本更高；该初版及原结果保留。最终原型只优化真正的光标位置，并重新完成同范围校验。生产改动仅位于 `packages/semantic/src/index.ts` 的 `deepestLocalSyntax`，沿用上一轮服务刷新修复。
