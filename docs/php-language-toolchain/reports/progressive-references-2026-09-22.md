# References 渐进索引：首轮 Alpha 实施与验证

渐进模式在打开 Composer 项目后，先建立并校验逐文件的轻量符号摘要，再后台准备完整项目源码事实和框架路由；选中符号时预热该符号的语义引用。References 到来时复用同代任务与事实。轻量摘要只在磁盘内容 SHA-256 相同、文件未被打开缓冲区覆盖时排除明确无关的候选；不完整摘要、编辑、移动、Composer 或 Provider 输入变化均保守回退。`onDemand` 仍为扩展默认值。

Alpha Profile 可设置 `phpCompanion.indexing.mode=progressive` 和 `phpCompanion.indexing.referenceMemoryBudgetMiB=1536`。预算允许 768–4096 MiB，是后台准备的 RSS 软上限，不是进程硬内存限制；达到预算后停止推测性索引，主动 References 仍走完整按需路径。文件变化后以两秒防抖重新准备，不在每次按键后立即重扫项目。

最终候选修复 Symfony Provider 的依赖类型边界后，再做一轮独立空缓存冷查：渐进模式 9,719 ms，按需模式 9,461 ms，均为 174 处且位置摘要相同。单次差值 258 ms，样本量不足以证明稳定回退或提速。

对 `AdminSecuritySubscriber` 类声明的冻结样本对照揭示了按需路径原有漏项：它把加载的 vendor `EventSubscriberInterface` 当成项目类型交给事件 Provider，Provider 拒绝输入，只有 `services.yaml` 注册位置。修正输入边界后，按需与渐进模式均返回 **2** 处，位置摘要均为 `a759a3d96e47ff50a8a1072ebfdff0b8f5243271a1acab7145aa9238ef569dad`；第二处是该类中的 `KernelEvents::CONTROLLER` 订阅位置。按需耗时 3,135 ms，后台事实就绪的渐进模式耗时 2,878 ms。这两个查询的路径和缓存状态不同，时间只用于描述各自实际等待，不能当作严格性能对照。

选中预热的一次进程级峰值 RSS 为 1,396,024 KiB，低于默认 1536 MiB 软预算。后台准备本身约需 15 秒，预热后的低点击等待**不是**总冷计算量降低。预算触发时观测值可越过阈值，因为阈值按批次检查且已派发的 worker 任务仍在完成；这不是内存硬限制。

空缓存查询发出 50 ms 后取消，一次测量在取消通知后 492 ms 返回 LSP `RequestCancelled`（`-32800`），没有返回半成品引用。未保存注释的首次再查询虽保留已准备的源码事实，仍花 3,230 ms 重算失效的语义和容器结果；这是已记录的后续性能改进点，不能写成“编辑后即刻查询”。编辑前后位置摘要相同。另一个 stdio 反例在函数体新增 `get` 调用后，渐进模式无全项目候选扫描，引用从 2 处正确变为 3 处。移动引用文件的 stdio 反例确认旧路径消失、新路径出现。

## 验收边界

聚焦 stdio 测试覆盖实验性/渐进两种源码索引的早期选中、就绪后 vendor 接收者引用、未保存缓冲区和非 PSR-4 继承回退；首次打开磁盘内容未变文件与选中扫描并发时不会无故推进项目代际，避免点击重复扫描。完整语言服务器回归 261 通过、1 跳过；Core＋Symfony 打包扩展在隔离的 VS Code Extension Host 测试通过。用户实际 WSL Alpha Profile 的持续编辑和真实点击仍需另行验收；自动化不能代替后者。空缓存立即点击仍约 8–10 秒，独立性能 Goal 保持开放。冻结样本路径是本机临时目录，消失后必须重建一致样本，不得把正在修改的工作树沿用该摘要。
