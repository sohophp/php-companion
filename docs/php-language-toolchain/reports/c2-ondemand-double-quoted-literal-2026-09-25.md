# C2 按需跨文件诊断：双引号纯字符串

日期：2026-09-25。独立临时 Composer PSR-4 项目、PHP 8.5、默认 `onDemand` 的真实 stdio 回归；未修改业务项目或打包 VSIX。

`final class Service::call(int $value)` 的使用方传入 `"bad"` 时，跨文件参数类型诊断原本缺失。现有证明门禁仅接纳单引号字符串、整数及几个标量关键字。先把已有完整编辑链的调用改成双引号，初始诊断断言由通过变为失败（收到空集合）；随后在该门禁加入无反斜杠、无 `$` 插值的双引号纯字符串。仍由语义层决定实际类型是否不兼容，并保留唯一 PSR-4 声明、最终方法/类或精确接收者等原有证明要求。

修复后定向 stdio 测试通过：初始错参诊断、声明的未保存类型和 final 属性切换、参数提示、数值实参、关闭后的磁盘恢复、watcher 更新、局部变量与方法返回实参，以及连续打开/修改/关闭/文件事件后的旧诊断防护。语言服务器 TypeScript 构建通过。带插值或转义的双引号表达式仍不进入此直接字面量证明范围；它们需要独立类型来源证明。安装候选、Remote 与长期编辑仍按 C4 验收。

随后把语言服务器的字面量正则筛选收敛为语义层的 `directScalarLiteralArgument`：它复用已有的标量字面量解析，并核对语义分析得到的实际类型，避免两套语法规则继续分叉。新增真实 stdio 序列验证 `3.5` 和 `2.0` 传入 `int` 有错误、`0x2` 传入 `int` 无错误、`"bad"` 有错误、`"$dynamic"` 不被当作直接字面量发布跨文件错误；`2.0` 按 PHP 的浮点写法处理，即使其数值为整数。原完整编辑链也重跑通过。语义包和语言服务器 TypeScript 构建、相关 ESLint、差异检查通过。

## 完整插值字符串的类型反馈

后续补上了独立的语法树证明：整个实参必须是无解析错误的双引号 `encapsed_string`，才把 `"$dynamic"`、`"hello {$dynamic}"` 和含转义的插值表达式判断为 `string`。因此前段记录的 `"$dynamic"` 不发布跨文件错误是当时的保守行为，已由本节更新。拼接表达式、缺少结束引号和弱类型可转换场景不因这项改动产生新的跨文件类型不匹配诊断。SoPHP 仍要求唯一可证明的目标方法与接收者；这项证明只补充实参类型，不放宽跨文件目标识别。

当前语义包 394/394、定向真实 stdio 与完整 10 项 Open Source Pack 的 VS Code 1.139.0 Linux 源码宿主均通过。宿主在未保存地改为插值字符串后将错误范围落在整个字符串，去掉 `strict_types` 后撤回错误，恢复原调用后再次出现；日志 `/tmp/sophp-c2-interpolated-string-pack10-20260925.log`。安装候选、WSL Remote 和长期编辑仍待 C4 验收。

## 局部赋值后的反馈

再检查 `$text = "hello {$dynamic}"; $service->call($text);` 时，语义层已推断实参为 `string`，但按需跨文件证明链仍只接受局部标量字面量，因此漏报。红灯语义测试先确认缺口；随后在原有“紧邻的局部赋值、没有引用别名或中途改写”的证明中，允许赋值右值通过同一个完整双引号字符串 AST 检查。`$text = 42` 或中途可能修改 `$text` 时，不沿用旧的字符串诊断。
