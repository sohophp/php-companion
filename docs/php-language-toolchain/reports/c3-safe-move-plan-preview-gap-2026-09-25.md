# C3 Safe Move 规划结束到预览建立之间的文件变化

日期：2026-09-25。只修改 SoPHP 仓库和独立测试夹具；未修改业务项目，也未打包 VSIX。

## 问题

Safe Move 在服务端返回编辑计划后才抓取参与文件的本地快照。文件如果恰在这段间隔被外部进程改写，命令可能把新磁盘内容当作旧计划的基线。对未打开的关联文件，VS Code `openTextDocument` 在文件事件到达前还可能暂时返回旧文本；旧计划因此会进入预览，直到稍后的检查才被拒绝。

## 修复

- 在规划开始前保存源文件的文档版本与磁盘摘要；计划结束后先检查源文件未变。
- 保留服务器返回的编辑参与文件源码快照。建立预览前核对每个参与文件的文档文本；对于未修改的打开文档，还核对实际磁盘字节。预览确认后的既有版本与磁盘检查继续执行。
- 源文件或关联文件在规划后、预览前变化时，命令直接返回 `false`，不打开预览、不移动文件。

## 验证

隔离 VS Code 1.139.0 C3 源码宿主分别注入源文件和未打开关联文件的外部磁盘改写。修复前关联文件场景触发断言：旧计划进入了预览；修复后两种场景均在预览前拒绝，外部内容保留，目标路径不存在。同一宿主的正常 Safe Move、一次 Undo/Redo 与其余 C3 序列通过，退出码 0；日志为 `/tmp/sophp-c3-safe-move-related-plan-gap-fixed-20260925.log`。根扩展与测试 TypeScript、改动文件 ESLint 通过。

这一门禁覆盖规划返回后的确定性时间窗口。安装候选、WSL Remote、真实 Explorer 交互及更复杂的未保存关联文件并发变化仍需单独验收。生成新文件的一次 Redo 仍为独立开放项。
