# 持续编辑基准异常退出清理修复

本批修复 `scripts/benchmark-editing.mjs` 在 Linux 中复现的真实进程泄漏：服务器暂停后，请求仍按原期限超时、基准以退出码1结束，但原清理只发送终止信号，暂停的自有服务器仍存活。修复及本批独立审计通过；生产 Core `8e1a08c7` 保持。

## 失败与修复证据

在独立进程组启动正常服务器，按父子关系、命令和启动标识确认自有 PID 后用 `SIGSTOP` 暂停。原基准在10秒协议超时后退出1，14秒观察时服务器仍为暂停状态，须由故障驱动回收。临时目录已删除，问题是残留进程，未将它描述为目录删除失败。

现在从进程启动时保留同一个退出 Promise，正常停止使用它等待真实退出。异常清理先向自有子进程发送终止信号，1秒清理宽限后仍未退出则强制终止；等待退出后再删除项目目录。原请求期限、错误内容、失败退出码与500/150/100ms性能门槛保持。

同一故障修复后通过：仍观察到真实超时与退出码1，服务器已退出，不需驱动回收，目录清理通过。新增[真实进程回归用例](../../../scripts/test/benchmark-editing-cleanup.test.mjs)约11.10秒通过。它在逐字还原的旧基准私有副本上因“必须自行回收服务器”断言失败，证明可检出原缺陷。

该故障用例限定Linux的`/proc`身份检查和`SIGSTOP`机制；本次实际执行1项通过、零跳过，未将它转作Windows异常故障资格。新的20秒测试运行上限仅用于容纳既有10秒超时和清理，不改变原测试或性能期限。
