# C2 按需模式的同文件命名参数反馈

日期：2026-09-24。Open Source Pack 默认使用 `onDemand`。此前即使 PHP 8 调用和唯一声明都在同一个打开文件中，写错命名参数仍不会出现 `php.argument.unknown-named`，因为该诊断只在完整项目索引后发布。

现在不完整索引只检查声明 URI 与调用 URI 相同的签名；方法声明还要求已加载集合中的同名声明唯一。跨文件声明即使因另一个文件已打开而临时可见，也不会被用来发布确定的错误。重复命名参数、命名参数后接位置参数或展开参数只依赖当前调用文本，现也在未完成索引时发布。完整索引时维持原有范围。PHP 8 以下不启用这些命名参数诊断。

独立 stdio 先证明旧结果漏掉两条同文件错误和三种参数顺序错误，修复后在 PHP 8.5 得到函数/方法错误各一条、重复命名/位置参数/展开参数顺序错误各一条；另一个已打开文件的错误调用仍不被误报，未保存修正后全部消失。同文件声明从 `int` 改成 `string` 的另一项 stdio 回归也确认参数提示与参数诊断同步更新。语义层的跨文件 `localOnly` 反例通过。隔离 VS Code 1.139.0 默认 `onDemand` 宿主在独立临时 PHP 夹具中观察到参数诊断 5 → 0 的未保存往返，退出码 0。

本轮只修改 SoPHP 仓库和宿主临时夹具；不修改业务项目，不打包 VSIX。此证据不证明动态调用、尚未加载的跨文件声明或所有复杂调用组合都已覆盖。
