# 两次实参检查的签名复用调查

结论：**调查已收口，私有原型不纳入正式代码**。完整诊断与可见补全结果一致，但诊断 P95 变差，未满足稳定收益要求；当前正常构建 `41ae20f8` 保持。复杂 Controller 的原性能预算继续开放，功能扩展暂缓。

## 范围与假设

[规则计时](diagnostic-rule-timing-2026-10-13.md)发现，按需诊断发布连续执行本地和完整 `incompatibleArguments`，两次同步检查各约 440 毫秒。私有原型在这两次原方法调用之间复用既有签名缓存；仍分别返回本地和完整数组，外部诊断继续执行原证明和过滤，诊断顺序保持。

原型通过私有构建插件增加内部聚合方法，仅覆盖按需发布分支。缓存仅存活于两次同步调用，保留原八类递归状态保护及事实加载/恢复时的失效机制，不跨异步等待。生产源码、正常产物、用户命令、设置和插件接口均未修改。这与此前只在缺参检查单次内加入缓存的原型不同。

## 已执行并通过

- 正常协议、未采样、PHP 8.5/onDemand；固定真实项目副本中的同一 Controller，两构建各 25 轮相同编辑，包含防抖、传输与完整版本诊断接收。
- 每轮完整诊断摘要、可见补全字段摘要一致；补全排除内部 `data`，未测试 resolve。PHP 编辑样例中交替方法名与返回类型的断言均通过，业务文件磁盘内容保持。
- 2,085 个产品输入及 66,079 个项目输入前后摘要一致；正常构建与私有对照的服务器摘要相同。
- 两服务器及两驱动退出码为零，缓存目录清理；编排和上述进程均已退出，终态后 `/proc` 审计通过。

**已执行但失败**：原型稳定收益准入；两构建的复杂文件诊断 500 毫秒及查询 150 毫秒预算。
