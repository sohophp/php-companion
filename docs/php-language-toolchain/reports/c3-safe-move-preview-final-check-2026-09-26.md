# C3 Safe Move 在应用前再次核对预览

日期：2026-09-26。只修改 SoPHP 扩展源码和独立 VS Code C3 夹具；未修改业务项目，也未打包 VSIX。

Safe Move 原先在用户确认预览后检查一次差异标签是否完整，然后还会等待应用前的文件快照检查。如果在这段等待期间关闭预览，命令仍可能应用移动。现在把“预览必须仍完整”的检查放到最后一次文件快照检查之后、`WorkspaceEdit` 应用之前；关闭预览会拒绝移动。

隔离宿主新增负例：确认预览后、应用前关闭其中一个差异标签，命令返回 `false`，源文件内容保持原样，目标文件不存在。原有预览取消、预览关闭、并发磁盘变动、正常 Safe Move 和 Undo/Redo 也随完整 C3 宿主通过，退出码 0。扩展与宿主 TypeScript、相关 ESLint、差异检查通过。

本次验证是 VS Code 1.139.1 Linux x64 的源码隔离宿主；尚未进入冻结的 `15a5254` VSIX，也不等于真实 WSL Remote 人工操作。最终 `createFile` 兜底的 Redo 缺口不受此修复影响。
