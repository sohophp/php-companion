# 新建且未打开的文件参与方法家族重构

日期：2026-09-25。仅修改 SoPHP Language Server、语义层、测试与文档；未修改业务项目，未打包 VSIX。

## 复现与修复

新建接口、实现和调用文件后，仅打开接口并立即新增参数，隔离 C3 扩展宿主曾返回空计划；三个文件均打开时，同一操作通过。独立 stdio 测试进一步稳定复现：初始项目扫描完成后，发送两个未打开文件的创建事件并立即请求新增参数，修复前计划只含接口文件。

问题有两个环节：文件事件在异步检查路径后才加入待处理队列，重构请求可能越过事件；即使两个文件已经进入语义工作区，新增和删除方法参数仍要求每个实现文件持有打开编辑器保留的语法树。现在完整性请求等待此前收到的文件事件处理完成，并应用待处理文件；新增和删除参数对关闭的家族成员临时解析语法树，操作后释放。

## 验证

- 独立 stdio 新文件竞态测试先只得到接口编辑，修复后新增参数与删除参数请求都包含接口、实现和调用；既有打开缓冲区与文件事件回归也通过。两项定向 stdio 测试通过。
- 新增与删除方法参数的关闭文件语义反例先失败、修复后通过；语义包全套 **377/377** 通过。
- 语义与 Language Server 构建、改动文件 ESLint、`git diff --check` 通过。
- 独立 Linux VS Code C3 扩展宿主退出码 0：只打开接口文件时，三文件新增参数通过预览取消、应用及一次 Undo/Redo。日志：`/tmp/sophp-c3-unopened-family-add-20260925.log`。
- 同一条件下的三文件删除参数也通过预览取消、应用及一次 Undo/Redo；在计划请求前验证实现与调用文件未打开。日志：`/tmp/sophp-c3-unopened-family-remove-20260925.log`，宿主退出码 0。

这组证据证明当前源码在上述 Linux 宿主与明确发送文件事件的 stdio 场景可用；安装候选、WSL Remote、跨平台和持续使用仍需分别验收。生成新文件的一次 Redo 仍未恢复文件，C3 尚未完成。
