# D156：PHPDoc 回调重复调用的补全保持

## 缺口与修复

原 v79 的 72 条观察显示：第一次调用正常，但稳定参数、局部／独立 `@var` 和别名的第二次调用会丢失条件返回类型、成员补全及参数提示。原因是已有保护把声明后的任何变量引用都视为不可靠。

新增共享的读取识别：直接变量调用按被调用变量的精确范围判断；变量调用在解析事实中的 `kind` 留空，不能当作具名函数筛选。嵌套 `accept($callback())` 与构造实参先识别内部调用，再检查接收返回值的外部调用。已证明唯一声明且按值传参的消费者复用原参数事实；未知消费者、引用暴露／捕获、写入、未证明的控制流和其它用法继续保守。参数、局部注解与别名使用同一规则，返回类型、签名和首次类来源保持一致。

engine v79 → v80；事实 schema 未改。当前生产 bundle `ac2b0a0ec69643824faf0eba51ed4976d1d7b1914e985618781ff4929dd45458`。没有修改外部 stubs 数据或新增设置。
