# C2 快速编辑时的旧诊断发布

日期：2026-09-24。独立 Composer 项目、PHP 8.5、默认 `onDemand` 下，隔离 VS Code 1.139.0 源码宿主在同一未保存文件中快速切换 `stopNow(): never` / `void`。最后一次编辑为 `void` 后，原测试观察到诊断事件的不可达提示数仍短暂回到 10，再变为正确的 7。服务器原本为标准 LSP 诊断附带文档版本，但当前语言客户端的诊断队列只保留 URI 与诊断数组，应用时无法再比较版本。

SoPHP Core 现在与自己的语言服务器使用带版本的诊断通知。客户端在转换前后都核对打开文档的身份和版本，只把匹配当前缓冲区的结果写入 SoPHP 诊断集合。PHP 内容变化时先撤下该集合里的旧诊断；新结果到达后再显示。独立 stdio 客户端未启用此选项时继续接收标准 LSP 诊断；文件关闭仍由标准空诊断清理。此边界不会改变 VS Code 内建 PHP 验证或其它扩展的诊断集合。

验证过程：仅按接收时版本过滤仍观察到最后一次编辑后的旧 10 条事件，因为旧结果可能在编辑前已写入集合；加入编辑时撤下后，隔离宿主连续两轮通过 20 次快速切换加最后一次 `void` 编辑。最后一次编辑之后仅观察到集合清空和正确的 7 条结果，没有旧 10 条；最终可见结果为 7，缓冲区保持未保存，退出码均为 0。源码 Core + Symfony Extension Host 完整套件退出码 0；定向 stdio 证明版本通知包含文档版本，内容变化后会更新，关闭文件会清理。TypeScript、ESLint 与差异检查通过。

编辑后的短暂清空是当前明确的反馈方式；本轮没有测量清空持续时间或物理屏幕像素。真实 Profile、长会话、Remote 和其它系统仍需验收。此修复尚未进入先前 `c280d1c5` 私有 Alpha 候选，本轮没有重新打包 VSIX，也未修改业务项目。
