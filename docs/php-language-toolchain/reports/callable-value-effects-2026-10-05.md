# D85 Callable 的引用效果与当前值

## 修复范围

闭包按引用接收变量或通过 `use (&$value)` 修改外层变量后，原补全／Hover／实参诊断仍可能采用调用前的类型。相反，一个未使用的引用参数、闭包体中的同名参数赋值，也会错误地让外层变量丢失说明。

现在共享检查依据实际实参与参数映射以及可证明的引用捕获处理影响，覆盖直接闭包、别名、箭头函数、命名与可变参数、可调用对象、数组 Callable 和 first-class Callable。未知回调接收直接变量时撤回旧事实；省略的引用输出、不同变量的引用参数、按值捕获和未执行的闭包定义不改变该变量的事实。`$callback(...)` 创建 Callable，不当作调用；获得后的别名实际执行时再检查引用捕获。

复用已有绑定与参数事实：闭包／方法的参数检查可以跳过返回值推断，避免类型推断递归到同一个实参。条件块中的局部绑定只接受同块前序赋值，有 `goto` 或不可靠位置则不证明；原普通签名深度预算保持，效果证明沿用 16 层预算。查询缓存按源码修订失效，最多 1024 项，递归有界，没有新设置或 Provider。

文本中的赋值／引用检查现在核对实际词法作用域；闭包内部的同名变量不作为外层已发生的赋值。已知引用调用也会撤回参数和构造值的旧成员类型。未保存改变闭包参数后，类型、诊断和说明撤回／恢复。
