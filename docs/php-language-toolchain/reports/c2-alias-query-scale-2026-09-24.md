# C2 双路径局部查询规模基准

日期：2026-09-24。使用 SoPHP 仓库内独立临时 Composer PHP 8.5 项目、真实 Language Server stdio 和默认 `onDemand` 模式。脚本 `node scripts/benchmark-c2-alias-queries.mjs <已打开文件数>` 创建真实路径与目录符号链接两份未保存标签页，让链接路径拥有跨文件项目事实，并在非所有者的真实路径标签页查询本地方法 Hover。分别记录首次查询、随后 10 次缓存命中、所有者未保存编辑后的重建，以及进程内存。没有修改业务项目或打包 VSIX。

初版局部视图每次重建都会重新解析全部已加载项目源码，包括 PHP 内建桩。32 个已打开文件时首次 Hover 646 ms、重建 625 ms；256 个文件时首次 709 ms、重建 642 ms。项目事实归属虽正确，这种等待不适合普通编辑。

现在视图共享主工作区已解析的只读文件事实，复制独立的查询缓存和文档索引，再解析查询标签页自己的未保存内容。打开/关闭标签页的拓扑版本、该标签页版本和主工作区语义修订共同决定缓存是否有效；所有者或 Provider 事实变化时重建。共享文件事实不因视图释放而修改主工作区。

| 已打开文件 | 首次 Hover | 10 次缓存命中 | 所有者编辑后重建 | 样本状态 |
| ---: | ---: | ---: | ---: | --- |
| 32 | 21 ms | 2–4 ms | 8 ms | 优化后，本机一次运行 |
| 256 | 32 ms | 2–3 ms | 27 ms | 优化后，本机一次运行 |
| 1,024 | 112 ms | 28–37 ms | 86 ms | 优化后，本机一次运行 |

32/256 文件的初版与优化后运行使用相同脚本和本机环境，但为不同进程，数字仅用于定位量级，不是严格配对性能证明；样本不能估计 P95。表中 1,024 文件的热查询区间是在刚收到全部打开诊断后测得，后来发现它包含请求等待，不能直接归因于语义查找。

为拆分这段等待，基准现在接受第二个参数作为打开文件后的静置毫秒数，默认为 1,000；同时记录五次轻量测试请求和语言服务器内部的查询视图、框架上下文、成员查找及完整 Hover 用时。本机 1,024 文件新样本如下：

| 静置 | 空请求端到端 | 热 Hover 端到端 | 服务端完整 Hover | 首次 / 所有者编辑后 |
| ---: | ---: | ---: | ---: | ---: |
| 0 ms | 15–27 ms | 12–25 ms | 0.4–1.1 ms | 68 / 60 ms |
| 1,000 ms | 17–24 ms | 前七次 15–23 ms，末三次 1–2 ms | 0.4–1.5 ms | 155 / 60 ms |
| 5,000 ms | 0.4–1.5 ms | 1–2 ms | 0.3–1.0 ms | 70 / 45 ms |

空请求与 Hover 同步变慢，说明早期端到端等待主要在请求处理之外；静置后消失。该实验尚未单独证明等待来自哪一项后台任务或进程调度，不能据此声称已修复繁忙期间的交互排队。静置后的首次构建和重建仍分别约 70/45 ms，后续以真实连续编辑的 P95 与取消响应检验。基准只验证隔离 stdio；完整 Pack、WSL Remote、Windows/macOS 与数小时持续使用仍待验收。

优化后语义包 320 项、语言服务器完整套件 18 文件 338 项通过、1 项跳过，相关 TypeScript 构建、ESLint 与差异检查通过。隔离 VS Code 1.139.0 Linux 源码宿主的 C2 编辑链再次通过，双路径场景仍显示项目使用方 `linkedOnly()`，真实路径标签页的 Hover、补全、Definition 使用 `realOnly()`，宿主退出码 0。宿主只验证了结果和基本操作，没有对完整 Pack 或真实 WSL Remote 做性能统计。

## 连续所有者编辑

基准增加连续轮数参数，每轮未保存地改动项目事实所有者，等其版本诊断发布，再查询另一标签页的本地 Hover；末轮额外检查项目使用方补全仍指向最新所有者。初次 1,024 文件、50 轮样本的 Hover 端到端 P50/P95 为 286.9/338.2 ms。20 轮分段复测表明，服务端局部视图重建阶段 P50/P95 为 74.7/132.0 ms，且每轮只有一条相关诊断，因而这次不是大量通知造成的测量假象。

原因是编辑所有者时，双路径清理反复对已不存在的另一 URI 调用 `remove()`；语义工作区原先把这次空移除也记为修订，使局部视图误以为其它项目事实变化并复制所有文档索引。现在空移除不增加修订；最近 512 次真正变更保留 URI 记录，若变化只来自局部视图已排除的所有者 URI，则直接复用视图。其它文件、Provider 事实变化或历史不足时仍重建。

修正后、本机静置 5 秒的独立样本：256 文件 20 轮 Hover 端到端 P50/P95 为 1.1/1.8 ms；1,024 文件 20 轮为 1.2/1.7 ms，服务端局部视图阶段 P95 约 0.3 ms。每轮均验证本地方法，末轮项目补全只含最新所有者方法；两次运行分别有 20 条版本诊断。进程 RSS 在 1,024 文件样本的前后约为 162/164 MiB。这些是单次隔离 stdio 序列，不代表完整 Pack、Remote 或真实用户长会话的 P95。

最终语义包 321 项、语言服务器完整套件 18 文件 338 项通过、1 项跳过，相关 TypeScript 构建、ESLint 与差异检查通过。隔离 VS Code 1.139.0 Linux 源码宿主又执行 10 轮双路径未保存编辑：每轮项目补全跟随最新链接标签页，真实路径标签页 Hover 始终来自自己的声明；这 10 次 Hover 的本机样本 P95 为 5 ms，两份声明均未保存，宿主退出码 0。样本数量不足以估计长期 P95，且不覆盖完整 Pack 与 WSL Remote。
