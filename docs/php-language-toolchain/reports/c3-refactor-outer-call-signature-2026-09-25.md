# C3 方法调用定位：末尾为旧式数组的实参

日期：2026-09-25。范围是 SoPHP Core 的方法参数新增、删除及重排计划；使用独立 PHP 夹具，没有修改业务项目，也没有打包 VSIX。

此前重构在调用的实参列表尾部查询方法签名。调用 `run($first, array('x'))` 时，该位置可能落在内部 `array(...)` 调用上，导致外层方法签名无法识别，整个参数重构计划返回空结果。现在五条 C3 参数重构路径统一从外层调用的第一个实参起点查询；无实参时使用外层左括号后的原有定位方式。

新增了跨方法家族新增/删除参数，以及私有方法新增/删除参数的旧式数组回归。修复前两个方法家族用例失败，修复后新增方法家族 4/4、删除方法家族 4/4、私有新增 6/6、私有删除 4/4、重排 6/6 通过。语义包 typecheck、修改文件 ESLint 和差异检查通过。`pnpm test:extension:c3` 的隔离 VS Code 宿主退出码 0，日志为 `/tmp/sophp-c3-refactor-outer-call-signature-20260925.log`；宿主覆盖既有 C3 工作流，新增的旧式数组场景由语义测试证明，不能当作已在真实编辑器逐步操作过。

生成文件的一次 Undo 后 Redo 不恢复仍是独立的开放问题，本次修复不改变该门槛。

随后补充的反例：`dispatch(/* reason (optional) */ 'x')` 在原先“第一个实参起点”定位下返回空计划，因为注释里的括号打断了签名匹配。回归先红后绿；现在优先在外层调用左括号后查询签名，只在该位置无法唯一识别时才使用第一个实参起点回退，以保留此前有多个候选时的收窄行为。语义包 360/360、typecheck、修改文件 ESLint 与差异检查通过；独立 `pnpm test:extension:c3` 宿主退出码 0，日志 `/tmp/sophp-c3-leading-comment-signature-20260925.log`。新增注释反例由语义测试证明，宿主检查已有 C3 操作无回归；生成文件 Redo 仍开放。

同一旧定位方式还影响参数 Rename：`dispatch(label: 'x', payload: array('y'))` 的 `$label` Rename 原先漏掉调用处 `label:`。私有方法和接口实现家族的两个反例现共用外层调用定位，均包含声明、方法体和命名实参位置。修复前私有方法反例先红，修复后语义包 362/362、typecheck、ESLint 和差异检查通过；独立 `pnpm test:extension:c3` 宿主退出码 0，日志 `/tmp/sophp-c3-named-array-rename-20260925.log`。新增两个反例的精确位置由语义测试证明；宿主核对既有 C3 操作没有回归，尚未单独执行这两个新场景的真实编辑器操作。
