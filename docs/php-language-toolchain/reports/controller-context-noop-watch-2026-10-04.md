# Controller 准备结果与重复文件通知

## 修复范围

此前，已加载、未打开且内容没有变化的 PHP 文件收到 changed 通知，也会使 Controller 候选失效，下一次查询重新 Finding。新增 PHP 7.2／8.5 协议回归；修复前 PHP 7.2 用例失败：Provider 被调用两次，预期一次。

现在仅对已知、关闭、大小受限且实际路径一致的普通 PHP 文件核对原始字节；确认内容未变后保留准备结果。有可能的打开缓冲区别名、符号链接路径、正在索引、未知源码、创建／删除或特殊配置输入时继续原有刷新流程。读取后再次检查 workspace 与来源，避免异步检查覆盖新状态。

interop 查询等待此前收到的文件通知处理完成，真实修改后立即查询也能取得新结果。回归覆盖相同内容重写、重复通知、真实修改、删除及重建。

- 最终源码 Language Server 构建和 Core production bundle 成功；根目录与隔离 Extension Host 的 TypeScript noEmit 检查通过。

- 使用当前源码 bundle、现有 Symfony Provider 和独立临时缓存，对 Winstar 只读查询：初始结果 24 个上下文，扫描 2541 个文件、解析 197 个候选。后续 20 次模拟 changed 通知与 10 次立即查询均保留相同结果；共一次候选扫描，一次 Finding begin／end，没有协议错误。
