# D86 诊断恢复搜索的按需执行

日期：2026-10-05；基于 `d6078507`。本批只修改 Core 诊断分析中的两处搜索入口。

## 改动与边界

当前普通连续编辑的独立 CPU 采样中，`clone(...)` 恢复正则在完全没有 `clone` 的文件仍消耗约 393.60 ms。现在先用大小写不敏感的字样检查；没有可能的 `clone` 或 `__construct` 时跳过对应恢复搜索。有可能的字样时，继续原来的全部匹配、语法树归属、参数校验和错误范围恢复。注释或字符串中的假字样不会提前结束后续真实匹配。

解析结果复用与增量解析已经存在，本批没有重新实现它们。解析器、语义源码、25 ms 诊断合并及前台／后台调度保持原有输入与行为。

同一声明夹具的两项搜索，交替执行五组各 100 次，单次中位成本 3.945→0.134 ms。这只能证明此处无候选搜索的成本下降，不能代表 LSP、整个文件诊断或可见弹窗的等待。

## 验证

- 原 90 份隔离宿主 PHP 输入及 12 份对抗输入，在 PHP 7.2、7.3、7.4、8.0、8.1、8.2、8.3、8.4、8.5 九种配置下，918 次完整诊断与符号对照相同。覆盖大小写、Unicode 偏移、假注释／字符串先出现、有效与无效 clone 参数、final 构造属性和相邻未完成语句；磁盘不变。
- 现有完整分析相关三文件／54 项通过，零跳过；其中 PHP 版本矩阵及错误恢复断言保留。
- 两文件／六项定向 stdio 通过，复测当前补全、说明、Hover、诊断版本与未保存编辑；不能称作完整 LSP 回归。
- 隔离 Linux VS Code 中 16 次可见首项接受、精确文本／光标、Hover Provider 和 Undo/Redo 通过，磁盘不变。可见等待为 131–261 ms；这是预加载后显式触发的宿主测试，不是真实 WSL 或自然输入的性能资格。
- Language Server TypeScript 构建、正式生产构建、ESLint 和 diff 检查通过。

对照工具首次因 TextDocument 导入路径、随后因 ESM 打包中的动态 require 启动失败，均发生在比较开始前；改为工作包解析依赖及 CommonJS 后，完整 918 对照通过。记录保留，不冒称首次即通过。
