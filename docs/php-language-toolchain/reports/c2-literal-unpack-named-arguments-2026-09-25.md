# C2 字面量数组展开后的参数反馈

日期：2026-09-25。目标是让编辑 `call(...['local', 80], t` 或 `call(...['port' => 80], ho` 时，参数提示与命名参数补全继续依据可确定的数组元素工作。

`signatureContext` 现在按源码顺序读取已完成的字面量数组展开。普通元素占用下一个位置参数，简单字符串键占用同名参数；`...[]` 不占参数。动态展开、动态键、显式数字键和数组内再次展开仍视为未知，不给出可能重复的命名参数建议或错误的参数高亮。此规则只处理完整的数组字面量，不据此推断变量中的数组内容。

验证：Pack manifest 4/4；语义测试 391/391；定向真实 stdio 1/1；VS Code 1.139.0 隔离 C2 源码宿主退出码 0，并观察到字面量位置参数展开后的第三参数高亮和 `tls:` 补全，以及动态展开后的提示抑制；相关 TypeScript、ESLint 和 `git diff --check` 通过。宿主日志：`/tmp/sophp-c2-literal-unpack-20260925.log`。没有重新打包 VSIX，也没有修改业务项目。

该证据适用于源码宿主；已安装的私有 0.4.5 候选早于本修复。WSL Remote、跨平台和持续使用仍按 C4 门槛验收。SoPHP 下一步继续以当前 10 项 Open Source Pack 为组合基线，检查未保存编辑、文件事件交错时的 C1/C2 反馈，再处理 C3 的可复现编辑闭环缺口。

随后用本机 PHP 8.5 CLI 核对位置和字符串键数组展开均按预期调用；“字符串键后再出现位置元素”抛出 `Cannot use positional argument after named argument during unpacking`，语义层现把这种数组保持为不确定，不显示看似确定的剩余参数。全套语义测试仍为 391/391。当前 10 项 Pack 的 VS Code 1.139.0 隔离源码宿主也增加了未保存 `...[1, 2]` 输入后的第三参数高亮与 `third:` 补全断言，日志 `/tmp/sophp-pack-source-literal-unpack-20260925.log`，退出码 0。该组合宿主使用 PHP 8.5 和独立 Composer 工具；未打包 VSIX。

源码组合测试入口现可用 `PHP_COMPANION_TEST_VSCODE_EXECUTABLE` 指向已缓存的 VS Code 可执行文件。首次运行因缺少隔离扩展目录变量，在宿主启动前退出；补齐现有隔离工具路径后组合门禁通过。入口改动避免了每次试验下载最新 VS Code，与 Core C2 宿主的同名变量一致。

语义回归还验证了数组位置元素包含嵌套函数调用的情况：`...[strtolower('LOCAL'), 80]` 仍占用两个参数，不把内部调用的逗号或括号当作外层实参边界。定向语义测试通过。
