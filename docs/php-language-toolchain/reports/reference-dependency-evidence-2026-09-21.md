## 已接入的读取证据

`hydrateCanonicalTypes()` 现在为每个语义工作区记录成功加载文件的 URI、路径和源码 SHA-256，并记录 ENOENT 的具体查找路径。已有 16 个候选上限保持不变；发生截断、非普通文件、文件大小超限或非 ENOENT 读取错误时，证据不可用于复用。记录最多 4,096 路径，超过上限同样拒绝。记录随工作区生命周期释放，未改变正常查询返回路径。

输入快照增加明确验证过的 `missingPaths`。核对时，“没有访问过某路径”不能冒充“该路径不存在”；成功读取的摘要必须与当前磁盘或对应未保存缓冲区一致。曾成功加载但后来读取失败的路径，不被当作已有语义事实已经消失。

新增仅 `testMode` 可用的 `phpCompanion/testReferenceInputs`：

- 自动收集工作区已加载来源与规范类型加载中的成功/缺失记录。
- 校验项目源码、真实 Composer vendor-dir 下的元数据、依赖 composer.json，以及上述路径。
- 捕获前后检查文档版本、项目/索引代次、语义来源和读取记录是否变化。
- 重新读取 Composer 项目并与消费的配置快照比较；注册了语义/路由 Provider 时拒绝，因为它们的权威输入尚未纳入。
- 只返回计数、指纹与状态；不返回源码，不存储或返回旧 References 结果。`semanticCoverageVerified` 仍为 false，因为实际引擎构建身份和完整框架事实尚未闭合。

基准通过 `PHP_COMPANION_BENCHMARK_REFERENCE_INPUTS=1` 启用该审计，默认运行不增加审计请求。
