# D84 补全、Hover 与实参诊断的控制流事实

## 修复

未知具名调用接收变量后，补全已经撤回类型说明，但 Hover 和严格类型实参诊断仍采用调用前的 `string` 判断。现在三个入口复用同一未知调用与收窄稳定性检查；不能证明调用后的值时，不再用入口参数声明报确定的类型错误。

重新赋值或重新进行合法类型判断可以恢复证据。未声明类型的变量经过内建 `is_string` 判断，也能提供具体 Hover 和实参诊断。按值调用、无关变量调用、原生 `isset`／`empty` 和类型谓词保留已有判断；同名业务函数依照实际解析结果处理，不能作为原生谓词。

这不是全部动态调用的效果分析。变量调用仍依赖现有 Callable 绑定／引用证明，本次共享检查不递归解析它们，以免类型查询反过来阻断闭包调用的类型推断。别名逃逸、动态绑定、表达式包装的实参和所有合流不作为已关闭范围。原参数、引用与动态语法保护没有整体移除。
