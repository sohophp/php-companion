# Linux 编辑器激活：九 PHP 版本与三索引模式（2026-10-10）

PHP 7.2、7.3、7.4、8.0–8.5 的九个实际 CLI，分别以 onDemand、progressive、experimental 测量 Linux Core 激活首次结果：每组 1,000 个实际 PHP 文件、五个全新工作区和用户目录，共 27 组、135 轮、405 次首次公开 Completion/Hover/Definition，全部严格校验通过。正常八运行资产逐字保持，日常 Profile 未更新。

## 工具与实际配置

[可复用工具](../../../scripts/benchmark-editor-activation.mjs)从给定 CLI 检出 PHP 目标，记录 wrapper 与其 `PHP_BINARY` 指向的实际 executable，并用 `--modes` 预先固定三种启用索引的模式。宿主证明与外层结果分别核对 PHP 目标、CLI 配置、索引模式和实际文件数，首次补全仍验证首项、完整签名、Snippet 与替换范围，Hover 和 Definition 保持原内容及精确位置要求。没有查询预热、结果轮询重试或强制 GC。

测量通过私有 main 时钟包装与 Production context 代理调用逐字不变的正常 bundle，向宿主返回原激活 Promise/API。每轮只发起第一次公开查询；计时从调用原 `activate` 前开始，包含激活完成、文档打开和首次查询等待。当前编辑器为 Linux VS Code 1.140.0。

## 失败、冻结与终态

新增运行时探测最初使用 `json_encode`，实际最小 PHP 7.3 `-n` CLI 没有该扩展，预检退出 255、编辑器样本为零。该原始失败保留；探测改为仅用核心语言输出 `PHP_VERSION` 与 `PHP_BINARY`。九个实际 CLI 均通过新版预检及旧输出目录保护检查，工具定向 ESLint 退出 0，语法/参数/实际 CLI 检查共 23 项通过。没有把预检失败写成产品功能失败，也没有通过重跑失败的编辑器轮次取得资格。

18,167 个唯一输入文件与 1,367 个链接的摘要在各轮运行及联合终态核验中保持一致；135 个宿主、135 个语言服务器和 135 个自有显示进程已退出，所有临时观察扩展和夹具删除。135 份服务器日志确认启动且无 test-mode 标记。4,252 个归档文件逐项核对摘要，包含实际结果、原始宿主日志、工具/控制器、正常八资产、预检失败及前置默认矩阵绑定；路径和摘要见同名 JSON。文档只在工作负载与归档核验结束后更新。
