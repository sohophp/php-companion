# C3 私有参数重构的无关同名方法误挡

日期：2026-09-24。源码 Extension Host 大套件在“删除未使用私有参数”处找不到重构动作。目标 `App\Formatter::format()` 只在当前类内直接调用，参数未使用且调用实参为安全字面量；同一 Composer 夹具另有 `\DateTimeImmutable::class . '::format'`，属于完全不同的类。

原安全检查在所有已加载文件中扫描包含 `::format` 的字符串，不比较这个由全限定类常量构造的调用目标，因此把无关类的方法后缀当成 `Formatter::format` 的潜在动态调用，错误地拒绝重构。现在只对**明确的其他全限定类**常量加同名方法后缀放行；目标类的全限定常量、动态类名和无法证明归属的写法仍拒绝。重构本身仍要求完整索引、唯一私有声明、未使用参数、可解析直接调用与无副作用的待删实参。

语义回归先证明无关类案例失败，再证明修复后返回动作，并逐项确认目标类和动态类名继续拒绝。SemanticWorkspace 与 F08 定向套件 **308/308** 通过；改动文件 ESLint、TypeScript 构建及 `git diff --check` 通过。源码构建后的隔离 VS Code 1.139.0 Core + Symfony Extension Host **退出码 0**，覆盖该动作的应用、Undo、Redo 及后续套件断言。测试夹具在宿主运行时显式设 PHP 8.5；未打包 VSIX。

此项是原宿主套件的误挡修复；它没有扩大到不完整索引、任意动态调用或工作区外引用。真实用户 Profile、Remote、跨平台和长会话仍须单独验收。
