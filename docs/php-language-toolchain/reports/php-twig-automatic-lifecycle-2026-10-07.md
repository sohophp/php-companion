## 原失败与对照

D264、D265 在删除已关闭标签页的 User.php 后错误要求撤回类型。实际 VS Code 仍把该文档保留为未关闭缓冲区，Core 发布的正是该缓冲区；关闭标签页不能作为 didClose 的证据。修正夹具后，保留缓冲区的删除与从未打开过的类型／Controller 删除分别验收。

D266、D267、D268 的删除类型检查仍失败，但实际 PHP payload 已为 `types: {}`，四个旧成员 Definition 均已撤回。候选都是 Text、无 PHP detail。D268 独立对照在原失败发生后关闭单词补全，两模板均为空；恢复原 `offWithInlineSuggestions` 设置，`code/role/title` 随即重现，证明来源是 VS Code 文档单词补全。五次原失败均保留，不作为产品缺陷或修复成功证据。

最终生命周期夹具仅在独立临时项目中设置 `editor.wordBasedSuggestions: off`，保持原 5 秒收敛上限，加入所有方法／属性候选的名称、kind、类型 detail、Hover 和精确 Definition 对照；未修改用户设置或通过丢弃 Text 候选取得通过。初始四项生产端控制通过、四项取消用例未选择，最终完整文件另行执行全部八项。
