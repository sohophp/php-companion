## 问题与改动

真实 Winstar 项目中，高频方法名 `get` 的首次 References 需要解析 1,647 个候选 PHP 文件。CPU 采样显示 Tree-sitter 解析、节点访问和语义构造是主要成本，候选摘要与快照压缩仅占较小部分。Parser 原先为命名空间和类型引用完整遍历一次语法树，随后为其余语义事实再次完整遍历。

现在有效 PHP 的命名空间声明从顶层节点收集；含语法错误的编辑中间态仍以完整遍历恢复命名空间。类型引用收集合并到原有的第二次完整遍历。这样有效文件只需一次完整节点遍历，仍保留所有类型引用上下文与 UTF-16 范围。

另试过让只因子串命中的热缓存文件仅恢复声明。Winstar 同一查询的位置保持一致，但热查询仅从 19.332 秒到 19.083 秒，单次差异不足以支持保留复杂分支；该实验已撤回，未进入本提交。
