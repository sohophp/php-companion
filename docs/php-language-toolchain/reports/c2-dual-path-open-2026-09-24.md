# C2 同一物理文件双路径打开

日期：2026-09-24。独立临时 Composer path repository 通过 `packages/local` 真实路径和 `vendor/local/package` 安装符号链接打开同一个 PHP 文件；只运行 SoPHP 仓库的默认 `onDemand` 语言服务器，未修改业务项目或打包 VSIX。

## 复现与处理

原先真实路径缓冲区的未保存 `betaOnly()` 已进入语义工作区后，再从安装链接 URI 打开同一文件并写入 `installedOnly()`，使用方补全仍返回旧 `betaOnly()`。两个 URI 的声明同时留在工作区，类型解析无法判断哪个缓冲区代表当前物理文件。

现在同一物理文件的跨文件语义事实由最近收到的打开/编辑事件拥有。新事件撤下另一 URI 的旧声明；两路快速编辑按事件顺序决定所有者，不按各文档互不相关的版本号比较。文件监视通知也选择最近编辑的打开缓冲区，不以磁盘内容或监视事件的 URI 覆盖它。关闭当前所有者后，仍打开的另一 URI 接管；两个都关闭后恢复磁盘事实。第一次发现两路未保存内容不同时，服务器向编辑器发送一次警告，说明当前归属并提示关闭一个标签页以消除歧义。

真实 stdio 用例覆盖真实路径和链接路径同时打开、反向快速编辑、夹在编辑之间的 watcher、先关当前所有者再关最后一个缓冲区，以及最终磁盘恢复；原有单缓冲区 10 次往返、链接/真实路径 watcher 和删除清理仍在同一用例中。当前所有者之外的标签页继续保留其 VS Code 未保存缓冲区，但跨文件项目结果采用当前所有者；在另一标签页发起的局部语义查询还需单独验收。此处是冲突场景的明确反馈与结果归属，不宣称两个互相矛盾的缓冲区都能同时成为项目事实。

首轮 Language Server 全套发现新增异步别名检查也运行于普通文件，导致 13 项首次/重载引用与框架用例读取旧版本。普通文件改为同步快路径后，这 13 项定向复测通过；最终完整套件 18 文件、336 项通过、1 项跳过。TypeScript 类型检查、相关 ESLint 与差异检查通过。Windows/macOS 实际宿主、完整 Open Source Pack、Remote 与数小时持续使用仍在 C4/组合门禁范围。

## 非所有者标签页的局部查询

后续回归确认了原有缺口：安装链接标签页成为跨文件事实所有者后，真实路径标签页内 `$this->betaOnly()` 的 Hover 返回空，即使该未保存文本仍在编辑器里。现在只在发起查询的 URI 被同物理文件的另一打开标签页取代时，建立一份局部查询视图：复制当前已加载的项目源码与 Provider 事实，排除同物理文件的项目所有者，再放入查询标签页的未保存文本。视图按标签页版本和项目语义修订缓存；项目本体和跨文件事实归属保持原状，标签页关闭后释放视图。

独立 path repository stdio 用例覆盖非所有者标签页的 Hover、成员补全、Definition 与 Signature Help，同时检查项目使用方仍只看到所有者声明；所有者再次未保存编辑后，非所有者的局部 Hover 仍来自自己的当前版本。语义包 319 项、语言服务器完整套件 18 文件 338 项通过、1 项跳过；TypeScript 构建、相关 ESLint 与差异检查通过。

隔离 VS Code 1.139.0 Linux 源码宿主进一步创建同一文件的真实路径与目录符号链接标签页，两边分别保留未保存的 `realOnly()` 和 `linkedOnly()`。项目使用方的补全只采用最新链接标签页的 `linkedOnly()`；真实路径标签页的 Hover、补全、Definition 都使用自己的 `realOnly()` 声明。宿主退出码 0。此证据不表示两个相互矛盾的缓冲区都成为项目事实；完整 Pack、Remote、Windows/macOS 和较大项目的查询等待仍须单独验证。
