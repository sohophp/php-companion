# References 方法名提前筛选实验（未保留）

日期：2026-09-21，产品基线 `c11784c`。

## 假设和边界

CPU 采样显示 `members()` 占用较多时间。实验为精确方法查询传入目标方法名，在构造参数和泛型返回信息之前过滤无关方法，并将名称传递到父类型和 Mixin。保留完整 Trait 成员以处理别名/优先级，保留属性层以免影响 Hook 合并。项目扫描范围及完整成员补全路径不变。

新增公共接口对照测试，核对按名称查询与完整补全在 Trait 别名、泛型父类、Mixin、PHPDoc 方法、属性大小写和链式返回上的一致性。291 项 Semantic 测试通过（14.82 秒），两项 References-first stdio 测试通过（8.21 秒）；相关构建、ESLint 和正式 bundle 构建通过。

## 同输入成对测量

每次启动独立 LSP 进程并使用空缓存；首先 References，然后 Definition，最后执行输入审计。第一组旧→新，第二组新→旧。四次都扫描 2,288 文件，均返回完全相同的 112 处 References 和 1 处 Definition。

第一组较快，反向运行未复现。候选阶段也有数百毫秒波动，证据不足以把总时间差归因于筛选。**实现和实验专用测试均已撤回**，恢复 `c11784c`，不将 8.314 秒作为当前产品性能承诺。

## 保留的工作方式

- 单点验证用相关包与明确的首次 References 用例，本次 Semantic 加 stdio 约 23 秒，不逐轮重跑完整打包与发布检查。
- 真实性能测量与构建/回归串行，检查完整位置摘要；需要对照时同时核对输入指纹并交换顺序。
- 收益未复现时终止实验，不无限增加验证轮次。后续优先消除已确认的重复读取/恢复，并继续补全安全持久化复用所需的候选读取集合证据。
