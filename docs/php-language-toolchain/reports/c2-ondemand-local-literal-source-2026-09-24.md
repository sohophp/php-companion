# C2 按需跨文件参数诊断的局部字面量来源

日期：2026-09-24。默认 `onDemand` 此前只对直接标量字面量实参发布已证明的跨文件类方法类型错误。日常代码常先把常量赋给局部变量再调用方法，因此 `Service::call(int $value)` 收到 `$value = 'bad'; $service->call($value);` 时虽能推得类型，却没有诊断。

现在同一规则还接受调用所在代码块内、可向前追溯到简单标量字面量赋值的局部变量。赋值与调用之间只允许无关变量的简单字面量赋值；实参必须是单一变量，调用必须是直接实例方法调用。原有 Composer 元数据完整、唯一 PSR-4 路径、唯一具体类与声明文件签名核对仍逐项执行。中间出现函数调用、无法证明来源的赋值、分支或方法返回来源时，这条新增规则不发布确定错误。完整索引模式的既有行为不受这项准入规则影响。

独立 Composer 项目的语言服务器真实 stdio 回归验证：声明在打开文件、磁盘 watcher 与使用方未保存编辑交错后，直接字面量及局部字面量变量均能报 `php.argument.type-mismatch`；变量经过函数调用，或来源改为跨文件方法返回时，按需诊断不再出现。语义包 319 项、语言服务器整组 stdio 158 项通过、1 项跳过；源码构建、ESLint 和差异检查通过。

首次整组 stdio 运行中，已有的实验模式跨文件 PHPDoc 用例把编辑后的第一条通知当成最终状态，因通知先后差异失败；该用例单独复跑通过。断言现等待预期的诊断状态，之后整组 stdio 复测通过。这修正了测试的时序假设，未更改实验模式的产品诊断逻辑。

隔离 VS Code 1.139.0 Linux 源码宿主在默认 `onDemand` Profile 中复核了局部变量编辑链：声明改为 `string` 时无错误，使用方改为局部字符串后把声明恢复 `int` 时出现错误；未保存地把局部赋值改成整数后错误消失，恢复字符串后重现；插入可能改写变量的函数调用后再次消失。直接读取编辑器可见 Diagnostics 集合，五个状态为 **无 → 有 → 无 → 有 → 无**，每次状态变化后持续观察 150 ms，无旧结果回闪。声明和使用方均保持未保存，宿主退出码 0；声明恢复 `int` 后首次可见诊断约 155 ms，仅为本机一次样本。

该支持域仍不覆盖跨文件返回值传播、条件赋值、别名或任意表达式。完整 Pack、较大 Composer 项目、WSL Remote 与长期使用仍需单独验收。此次未修改业务项目，也未为日常源码增量打包 VSIX。
