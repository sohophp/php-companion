# PHP 引用准备：压缩缓存与 Worker 恢复

## 原因与实现

此前缓存重启仍读取大份明文语义 JSON，并在主线程逐条核验快照。2026-10-04 的只读规模测量中，2538 个缓存条目的校验合计 1.38 秒、声明恢复合计 1.32 秒、轻量摘要合计 0.40 秒；缓存启动没有明显快于冷启动。

源码现在在 source-only 准备模式复用已有的有界压缩格式，并通过现有 CandidateWorkers 完成解压、完整快照校验及源码 hash 匹配。Worker 用 JSON 字符串传送恢复结果，避免深层对象的 structured clone 成本；声明更新仍在主线程按文件顺序执行。

保留每个源文件的 hash 验证。未保存缓冲区继续在主线程按当前文本核验；Worker 失败走原有恢复或源码重建路径。旧明文条目仍可读取，损坏压缩条目拒绝并重建，超出压缩预算时保留普通条目，不删除有效缓存范围。不改变设置及缓存版本，也不把快照校验省略当作性能优化。

## 定向验证

- 最终产品源码 Language Server 构建、Core production bundle、根目录和隔离 Extension Host noEmit 检查通过。
- 快照、Worker transport、真实 Worker Doctrine facts：10 项单元测试通过。
- 最终定向 stdio：5 项通过、440 项未选中，运行 27.04 秒。包括 PHP 7.2／8.5 各自的冷、压缩缓存、旧明文缓存、单条损坏、恢复期间未保存修改、取消六种进程路径，以及已有框架快照引用预热两种缓存路径和命名实参缓存恢复回归。
- 两版损坏条目路径均恢复 40/41 个缓存文件并重建剩余文件；旧格式恢复 41/41。恢复期间改成 `onlyEdited` 的未保存成员精确补全，磁盘仍为 `onlyItem`。正常路径只结束一次进度并报告 ready；取消不误报 ready。

## 实项目只读测量

Winstar 仅作约 2539 文件的规模样本，使用独立进程、临时缓存、Core progressive 模式，没有 Symfony Provider。每种实现只测一组冷／缓存启动；被测项目可能有外部编辑，不将该结果视为严格重复基准或性能预算验收。

| 实现 | 冷启动 begin→end | 缓存启动 begin→end |
| --- | ---: | ---: |
| 原路径 | 12.69 秒 | 14.22 秒 |
| 仅压缩实验 | 13.60 秒 | 12.60 秒 |
| 压缩与 Worker（保留方案） | 12.95 秒 | 10.11 秒 |

保留方案本轮缓存准备缩短约 29%，主线程恢复校验计时约 13.54 ms；该计时不包含 Worker 内校验。缓存准备后 `func` 首项为 `function`，查询约 32.77 ms，进度正常结束，采样业务文件字节不变。详细临时证据分别为 `/tmp/sophp-reference-cache-{profile,compact,worker}-20261004.json`。

本批不更新安装资产、Profile 或 VSIX，不推送。仍需真实 WSL 可见状态栏、Symfony 组合、冷／缓存长期会话和平台验收；不能称引用准备等待已经整体解决。
