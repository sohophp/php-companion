# 按需引用候选的持久语义快照

日期：2026-09-21。功能提交：`9e955173d72e359f459555669311547bf72ad2b7`。

## 问题与边界

真实 Winstar 的 `src/Security/AdminPasswordChangeGuard.php` 中，`$request->attributes->get('_route', '')` 的 112 处 References 在上一个候选的冷/热独立语言服务器进程均需约 41/40 秒。按需扫描在每次进程启动后都重新解析约 1,647 个包含 `get` 子串的项目文件；仅按独立 `get` token 缩小范围会丢失用于成员归属判断的类声明，因此不能直接替换现有保守候选规则。

现在按需候选缓存同时保存原有源码摘要和 checksum 校验的语义快照。后续独立进程若文件元数据、源码哈希、摘要决策、快照范围及校验和均有效，就恢复快照；打开的文档继续按当前缓冲区解析。更改后的文件重读并重建。过大或损坏的快照回退到源码解析，不把不完整结果当成零引用。快照使用有界 deflate 压缩，候选缓存版本升级到 v4。

使用相同 Winstar 文件与查询位置，分别启动全新的 LSP 进程，第二个进程共享第一个进程写入的缓存。定义和引用的位置按 URI 与行列排序后计算 SHA-256；与前一候选 `e3875c60` 的完整位置摘要一致。
