# D274–D277：分文件缓存原型未采用

日期：2026-10-07。产品 Core `0680ad5a`／TwigPlus `0ca45a6a` 保持；本批只在私有目录建立并验证不同的缓存存储方向，没有接入产品或修改原基准。[结构化记录](cache-entry-storage-experiment-2026-10-07.json)保留完整源码、命令、逐项结果、原失败和冻结审计。

## 方法与完整序列

现有通用缓存仍一次解析完整 manifest、保留全项目 payload。此前流式 JSON 和逐文件压缩已在 50k 失败，本次不重复这两种方案。隔离原型改为 schema 2：主清单仅含元数据与 blob 校验，payload 分文件读取；完整新一代文件准备后原子替换清单，提交时复用旧文件并清理被替换代，取消只移除自身暂存。旧 schema 1 可恢复后迁移。12 项基础控制通过，覆盖 Unicode／顺序、稳定热缓存、单文件校验损坏／adapter 拒绝、取消／提交竞争、旧格式、非法标识、格式错误尾部、删除和并发提交。

私有基准仅替换索引实现，并让损坏工具定位新格式中的同一 Base payload。工具更新外层 blob 引用／字节校验后保留原内层语义 checksum，仍真正触发派生层或 callable 检验失败。原四个完整加载阶段、全部热恢复／延迟实现／聚焦加载／损坏断言均保留；完整序列在同一进程完成，RSS 包括准备、修改、恢复和清理，没有强制 GC、分进程降低峰值或放宽预算。

## 接入保护失败与实际分配观察

后续三项保护检查全部失败：原型在序列化失败后没有完整保留旧缓存；schema 2 内联 payload 字段可绕过外层 blob 校验；死进程遗留锁不可恢复。原始失败与源码已保存。原型没有接入正式索引、Language Server、Profile 或安装包，不能将 10k 单次通过称为整体解法。

对当前真实 SemanticWorkspace 恢复 128 个独立 PHP fixture，保持全部实现 deferred，读取实际 property descriptor 的函数身份：12 个字段各有 128 个 getter，共 **1536 个独立函数**。这是实际分配形状观察，没有测量字节、堆泄漏或证明它是 RSS 失败根因。源码还显示 restoreDeclaration 在验证用 file 之后再次构造 deferred file。下一独立项评估共享访问器与复用已验证对象，并保护文件隔离、按 callable 延迟加载和所有快照校验；不再重复等价分文件／流式存储规模测量。
