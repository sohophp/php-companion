## 连续输入断言修正

首次复核两版均退出 0，但 8.5 的 func 截图读到了 function 首位和旧 f 前缀的 fclose 等候选。原断言只要求 function 首位并排除两个特定函数，可能在列表刷新前通过。

将 func／function 的等待条件收紧为每个可见候选均为 function 关键字或其声明模板，重编扩展测试后复核，两版均只观察到 function 和 function block。最终字符后的有界等待为 123／16 ms；包含 CDP 轮询，不是生产协议热查询 P95。没有据此修改产品补全逻辑。

8.5 日志中出现一次 VS Code renderer getItemsByProvider 未定义异常；随后可见列表与接受断言完成，宿主退出 0。此异常单列保留，不能据此宣称 renderer 全程无错误。详细证明行及日志路径见同名 JSON。

此前 72969／13216 两原会话属于收紧断言前的测试输入，保留为历史；不能用其过早读取的 func 列表证明最终刷新。当前终态冻结清单 /tmp/sophp-current-c1-strict-prefix-inputs.json，测试编译前后变化仅涉及测试输入，不涉及产品源码。
