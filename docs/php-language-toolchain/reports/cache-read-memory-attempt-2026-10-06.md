## 单一方案及结果

对原完整缓存序列做一次诊断观察，在整份 manifest 的读取、解析和序列化附近记录到大分配及高水位上升；带观察钩子的 10k 高水位为 1001.39 MiB。这是观察，不作为性能资格，也没有证明哪个对象被错误保留。

方案复用 [@streamparser/json](https://github.com/juanjoDiaz/streamparser-json) 0.0.26，以 64 KiB 块读取，避免完整项目 JSON 字符串；完整封装及尾部验证后才允许恢复，读取间检查取消，保留原格式、版本、重复字段语义及全部恢复断言。原型一次 10k 高水位为 761.38 MiB，热恢复 8704.69 ms；随后一次正式候选测量如下，未重跑失败轮或挑选最好样本。

旧 D118 单次热恢复为 5855.15／30704.71 ms，本候选为 9233.19／45711.72 ms。它们是不同批次的独立合成项目，不推导精确性能退化比例；但没有证明等待改善，50k 整轮内存也未达标。**方案全部撤回，不作为缓存内存问题已解决，不再重复这一方案的等价测量。**
